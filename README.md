# SamGuide — 심사청구 점검 참고자료

점검 로직을 짤 때 필요한 자료(본인부담금 규칙 · SAM 레이아웃 · 특정내역 · 산정특례)를
한 화면에서 찾아보기 위한 사이트. 브라우저 안에서만 동작하고 외부로 아무것도 보내지 않는다.

## 여는 법

`index.html` 을 더블클릭하면 바로 열린다. (빌드 · 서버 필요 없음)

주소창에서 열고 싶으면 `serve.ps1` 을 실행한 뒤 <http://localhost:8392> 로 접속한다.

## 자료 갱신일

화면 제목 오른쪽에 `자료 갱신 2026.01.01` 처럼 작게 붙는다. **고시나 엑셀이 바뀌면
`data/updated.js` 의 그 줄만 고치면 된다** — 화면 코드는 손댈 필요가 없다(`js/common.js` 의
`showUpdated()` 가 그린다). 커서를 올리면 어느 자료에서 온 것인지 출처가 뜬다.

날짜는 **원본에 적힌 기준일만** 쓴다. 파일을 만든 날이 아니다.
원본에 날짜가 없으면 `d:''` 로 두고 화면에 **"갱신일 미확인"**(연한 파랑)으로 나온다 —
추측해서 채우지 않는다. 틀린 날짜는 없는 날짜보다 나쁘다.

지금 날짜가 확인된 것은 셋뿐이다.

| 카테고리 | 갱신일 | 근거 |
|---|---|---|
| 본인부담금 계산기 · 특정내역 | 2025.08.01 | 세부작성요령 판 날짜 |
| 산정특례 특정기호 | 2026.01.01 | 파일명 `…등록기준(26.1.1.기준).xlsx` |
| (표에 붙는 특정기호 배지) | 2026.08.24 | 파일명 `특정기호_20260824.xlsx` — `SG_UPDATED_SYMB` |

**① 본인부담금 규칙은 여기서 그리지 않는다.** 제도별로 날짜가 달라(건강보험 2026.06.23. ·
의료급여 2026.07.30.) 화면 안 `b2-src` 에서 탭에 맞춰 따로 보여 준다. `data/updated.js` 에는
`d:''` 로 두고 출처만 적어 둔다.

### 검색 — 한/영 안 맞춰도 찾는다

**브라우저는 IME(한/영) 상태를 바꿀 수 없다.** CSS `ime-mode` 는 Chrome 이 지원하지 않고
(`CSS.supports('ime-mode','active')` = false), `inputmode="latin"` 도 반영되지 않는다.
그래서 강제하는 대신 **잘못된 상태로 친 글자를 자판 기준으로 되돌려 원래 검색어와 함께** 찾는다.

| 친 것 | 되돌린 것 | 어디서 |
|---|---|---|
| `ㅡㅅ001` | `mt001` | 한글 상태로 코드를 칠 때 (특정내역·산정특례 등) |
| `xmrwjdsodur` | `특정내역` | 영문 상태로 한글을 칠 때 (레이아웃·메모장 등) |

- `sgKoToEn()` / `sgEnToKo()` (`js/common.js`) — 완성형 음절을 초·중·종성으로 풀거나 다시 조합한다.
  두 글자 모음(`hk`=ㅘ)·두 글자 종성(`rt`=ㄳ)을 먼저 맞추고, 종성 다음이 모음이면 그 자음을
  다음 음절의 초성으로 넘긴다.
- `sgQueries(q)` 가 [원래 검색어, 되돌린 것] 을 돌려주고 `sgHit(글자, q)` 가 하나라도 걸리면 참이다.
  화면들의 `.includes(needle)` 자리를 이것으로 바꿨다(11개 화면 17곳).
- **입력칸의 글자는 고치지 않는다.** 고치면 특정내역에서 한글 명칭을 찾는 것 같은 멀쩡한 검색을 망친다.
- `hilite()` 도 되돌린 후보를 같이 칠한다 — 되변환으로 걸린 행에 표시가 없으면 왜 걸렸는지 알 수 없다.
  정규식을 쓰지 않고 `indexOf` 로 훑어 검색어에 정규식 특수문자가 섞여도 안전하다.

화면별 기본 입력은 `SG_IME` 에 두고 입력칸 끝에 `(한글)` · `(영문·숫자)` 로 적어 준다 —
되변환이 있으니 **강제가 아니라 안내**다.

| 한글 | 영문·숫자 |
|---|---|
| SAM 파일 레이아웃 · 항 · 목 코드 · 메모장 | 특정내역 · 산정특례 특정기호 · 약국 산정특례 · [별표12] 소아가산 · 응급의료행위 |

### 지난 판 보기

갱신일 배지를 누르면 판 목록이 뜨고, 고르면 **그 시점 데이터로 화면을 다시 그린다.**
지난 판을 보는 동안은 파란 띠("지금 기준이 아닙니다 · 현재 판으로")가 떠서 최신과 헷갈리지 않게 한다.
지난 판이 **없는 카테고리는 배지가 그냥 글자**다(눌리지 않는다).

지난 판은 `data/archive/<화면id>.<YYYY-MM-DD>.js` 한 파일에 담고, 그 파일은 한 줄만 부른다.

```js
SG_ARCHIVE_ADD('page-detail', '2025.08.01', (function(){ …옛 data 파일 그대로… })());
```

**미리 챙겨 둘 필요가 없다 — 저장소가 이미 모든 판을 들고 있다.** 나중에 필요할 때 뽑으면 된다.

```bash
git log --oneline -- data/detail-codes.js
```
```bash
powershell -File tools/archive.ps1 -Page page-detail -Date 2025.08.01 -Commit 8103a65
```

`-Date` 는 **고시·엑셀에 적힌 기준일**이다(커밋한 날이 아니다). `-WhatIf` 를 붙이면 만들 파일만 보여 준다.
스크립트가 옛 파일을 함수로 감싸(전역이 밖으로 새지 않게) 만들고, `index.html` 에
`<script>` 한 줄을 **`js/common.js` 뒤에** 붙인다 — `SG_ARCHIVE_ADD` 가 거기 있어서 앞에 두면 없는 함수가 된다.
`index.html` 은 공용 파일이라 팀원에게 알려야 한다.

돌아가는 데 필요한 두 가지가 있다.

- **데이터 전역은 `var` 여야 한다.** `const`·`let` 은 `window` 에 붙지 않아 지난 판으로 바꿔 끼울 수 없다.
  그래서 `data/*.js` 의 배열 선언을 `var` 로 바꿨다.
- **화면마다 다시 그리는 함수**를 `js/common.js` 의 `SG_RERENDER` 에 적어 둔다.
  새 카테고리를 만들면 한 줄 더한다 — 없으면 지난 판 보기 단추가 뜨지 않는다.

`tools/archive.ps1` 은 **UTF-8 BOM 으로 저장해야 한다.** PowerShell 5.1 은 BOM 이 없으면 ANSI 로 읽어
한글 주석이 깨지고 파싱이 실패한다. 파일을 읽고 쓸 때도 `[IO.File]::ReadAllText/WriteAllText` 에
UTF-8 을 명시한다 — `Get-Content -Raw` / `Out-File -Encoding utf8` 은 5.1 에서 한글을 깨뜨린다
(실제로 이걸로 `index.html` 을 한 번 깨뜨려 HEAD 에서 복구했다).

## 특정내역 데이터 다시 만드는 법

고시가 개정되면 새 「요양급여비용 심사청구서·명세서 세부작성요령」을 한글에서 **PDF로 저장**한 뒤
아래를 돌린다. `-table` 옵션이 3단 표(구분코드 / 특정내역 / 작성요령)의 칸 정렬을 살려주고,
`parse_특정내역.awk` 가 그 칸을 잘라 구분코드 단위로 나눈다.
쪽 범위(`-f` / `-l`)는 새 판에서 "Ⅸ. 특정내역 구분코드 작성요령"이 시작·끝나는 쪽으로 바꾼다.

```bash
pdftotext -f 211 -l 253 -table -enc UTF-8 "세부작성요령.pdf" sec9.txt
LC_ALL=C.UTF-8 awk -v START=211 -f tools/parse_특정내역.awk sec9.txt sec9.txt > sec9.jsonl
```

`LC_ALL=C.UTF-8` 이 없으면 awk가 글자를 바이트로 세어 칸 위치가 어긋난다. 반드시 붙인다.
같은 파일을 두 번 넘기는 것은 1차에서 쪽별 칸 위치를 재고 2차에서 자르기 때문이다.

그 다음 「특정내역코드_통합본.xlsx」(마스터)와 합친다. 엑셀은 Excel COM으로 시트를 TSV로 뽑아 쓴다.

```bash
LC_ALL=C.UTF-8 awk -v SEC9=sec9.jsonl -f tools/merge_detail.awk sec9.jsonl 통합본.tsv > merged.jsonl
```

결과 `merged.jsonl` 을 `data/detail-codes.js` 의 `const DETAIL_CODES = [` … `];` 안에 넣으면 끝.

- 통합본이 마스터인 이유: 분야(의과·산재·자보·DRG·신DRG·한방·요양병원)와 적용/종료일자가 있고 코드가 더 많다.
- PDF 본문은 건강보험 의과 기준이라 코드는 적지만 예시·표가 붙어 있어, 코드가 겹치는 **현재 판**에만 붙인다.
- 통합본에 없고 PDF에만 있는 코드는 `onlyPdf:true` 로 표시되어 화면에서 "분야 미상"으로 보인다.

### 본문은 줄 전체를 쓴다 — 칸 좌표를 하나로 (2026-08-21)

`parse_특정내역.awk` 는 예전에 본문(3단)을 **3단 시작 위치부터 잘라** 담았다. 그러면
첫 단 자리까지 삐져나온 줄(MT018 본인부담구분코드 표)은 줄 전체를 쓰고, 그렇지 않은 줄은
잘라 써서 **줄마다 칸 좌표가 달라졌다.** 그래서 원문에서 칸 안의 글자가 다음 줄로 넘어간 것이
왼쪽으로 밀려, 화면에서 **다른 칸에 붙어 보였다** — MT018 M013·M014 의 `노숙인 1종` 이
대상 칸이 아니라 구분코드 칸에 들어갔다.

이제 이름 단이 끝난 뒤로는 **줄 전체**를 본문으로 쓴다(공통 들여쓰기는 `flush()` 가 걷어낸다).
`data/detail-codes.js` 는 2026-08-21 에 이 스크립트로 다시 만들어 **본문 114건의 들여쓰기만**
바뀌었다(글자는 114건 전부 그대로 — 공백을 뺀 글자열을 예전 값과 대조해 확인했다).
본문만 갈아 끼웠으므로 분야·적용기간 등 통합본에서 온 값은 손대지 않았다.

## 레이아웃 데이터 갱신하는 법

SAM 레이아웃은 `D:\Documents\Desktop\SamEditor` 의 것을 **복사해서** 쓴다.
SamEditor 쪽 레이아웃이 바뀌면 아래처럼 다시 복사하면 끝이고, 이 폴더에서 직접 고치지 않는다.

```bash
cp "D:/Documents/Desktop/SamEditor/js/"layout-*.js "D:/Documents/Desktop/SamGuide/js/"
```

`layout-shim.js` 는 SamEditor 의 `common.js`(편집기 본체) 없이도 레이아웃 파일이 로드되도록,
레이아웃 파일이 로드 중에 부르는 함수(`F` · `codesTable` · `registerClaimType` 등)만 흉내낸 파일이다.
복사한 레이아웃 파일이 새로운 전역 함수를 쓰기 시작하면 여기에만 한 줄 추가하면 된다.

### 청구서(H010) 항목설명 — 092 문서 원문으로 채움 (2026-08-21)

`LAYOUT_H`(청구서)는 GEN · DRG · 신포괄 · 의료급여정액 · 한방 · 첩약이 **함께 쓰는 공통 서식**이다.
설명이 「명세서 합계」처럼 줄여 적혀 있었는데, 아래 문서의 「코드 및 유형」 칸을 **줄이지 않고 그대로**
옮겼다(SamEditor `js/layout-gen.js` 에서 고치고 복사).

| 원본 | 내용 |
|---|---|
| `★ DRG SAM 청구서 (092).doc` | `D:\Documents\Desktop\질의 참고파일\SAM\2. DRG (092)\건강보험 092버전-DRG 서식 개편\1.SAM자료\1-2.변경문서\` |
| `SAM_01_청구서(092간지포함).doc` | 같은 폴더. **두 문서의 표 내용이 글자까지 동일**(청구서는 공통 서식) |

문서 머리말: `SAMFILE-ID H010` / `SAMFILE-NAME 요양급여(의료급여)비용 심사청구서 (공통) – 092Ver`.
필드 39개 · 레코드 2,096 byte — 위치·길이는 예전과 **한 자리도 다르지 않다**(설명·코드값 문구만 채움).

옮기면서 판단한 것 세 가지:

- **청구서/명세서 서식버전** — 문서에 적힌 값 `‘092’` 를 그대로 넣었다. 예전 표기는 `'091'/'089' 등`
  이었다. 한방 문서는 091 버전(`★ 한방 SAM (091).doc`)이므로, 한방 파일은 앞 6byte 가 `091091`
  일 수 있다 — 같은 공통 서식이라 화면에는 092 로만 보인다.
- **항목명은 예전 표기를 유지**했다. SamEditor 가 필드를 **이름으로 찾아** 청구서 합계를 다시 계산하기
  때문에(`총액2·진료비총액` · `100/100본인부담총액` · `100/100미만 본인부담` · `100/100미만 보훈청구`
  · `요양기관기호` · `보험자종별구분`) 이름을 문서대로 바꾸면 재계산이 끊긴다.
  대신 문서 항목명이 다른 6개는 설명 첫 줄에 `문서 항목명: …` 으로 적었다.
- **`( 의료급여, DRG 청구시는 ‘0’ 또는 ‘Space’처리 (`** — 문서에서 「100/100미만 보훈청구액」 줄과
  「차등수가 적용구분」 묶음 사이에 **표 전체 폭 한 줄**로 들어 있다. 차등수가는 의료급여·DRG 에서
  쓰지 않으므로 **차등수가 4개 항목**(진료(조제)일수 · 의(약)사수 · 차등지수 · 차등수가청구액)에 붙였다
  (예전에는 100/100미만 보훈청구액에 붙어 있었다). 앞뒤 `(` 는 오타가 아니라 **문서 원문 그대로**다
  (Word 에서 확인 — 굴림체 U+0028 두 개, 기호 폰트가 깨진 것이 아니다).

`진료형태`는 코드 하나에 분야별 뜻이 겹쳐(`1` = 의과입원 · 보건입원 · DRG 질병군 의과입원) 코드표로는
한 줄에 담을 수 없어, 문서의 분야별 목록을 **설명 칸에 그대로** 적고 코드 배지는 기존 통합 표기를 뒀다.

설명 칸의 줄 나눔이 보이도록 `css/style.css` 의 `.c-desc` 에 `white-space:pre-line` 을 걸었다.

### DRG 명세서(D020.1~.6) 항목설명 — 092 문서 원문으로 채움 (2026-08-21)

  다르다**(DRG 문서는 청구번호에 `DRG구분(D)`, 내역구분이 「‘D’: 처방내역」). 의과 쪽 문서는 091 버전

  틀어진다. 그래서 **의과·신포괄·의료급여정액·한방·첩약이 쓰는 공용 D/E 는 손대지 않았다.**
- **진료내역(C)에 T항(특수재료)이 없고, 열외군(F)에 L항이 없다** — 문서의 항 목록이 그렇다.
  예전에는 둘 다 공용 `항번호코드`(20항)를 써서 C 에 T, F 에 L 이 섞여 있었다. 문서대로 `DRG_항코드_C`(19항) ·
  `DRG_항코드_F`(19항)를 따로 만들었다. 「항 · 목 코드」 화면의 DRG 항 수가 이 때문에 달라진다.
- **목번호도 C·F 를 따로 만들었다**(`DRG_목번호맵_C` · `DRG_목번호맵_F`). 문서 문구가 서로 다르다 —

  12·13(사용유보)과 특수장비 04·05(사용유보)는 **F 에만** 있다. 문서에 적힌 순서를 지키려고 `codesTable` 로
  만들었다(그냥 객체면 `10`·`11`·`99` 처럼 숫자꼴 키가 맨 앞으로 밀린다).
- **진료과목은 DRG 문서의 26개만 담은 `진료과목코드_DRG`** 를 따로 뒀다. 공용 표와 달리 07 이 「흉곽외과」

문서에 「삭제 an(n) (구 ○○ 항목)」로만 남은 옛 항목(위치가 없어 필드가 아니다)과 문서 각주·기재 예시는
`js/layout-drg.js` 의 레코드별 주석에 그대로 적어 뒀다. 문서 오타도 원문대로 옮겼다 — 입원시상병유무 `Y` 의

## 본인부담금 계산기 — 원장 한 장 (2026-08-21)

사용자가 손으로 쓰는 계산지 모양을 그대로 옮겼다. **왼쪽 = 금액 · 오른쪽 = 그 금액의 본인부담**
한 표(`table.fields.items.led`)이고, 줄 순서도 계산지와 같다.

| 줄 | 왼쪽(금액) | 오른쪽(본인부담) |
|---|---|---|
| 첫 줄 | 총진료비 (요양급여비용총액 1) | **산정대상 금액 × 법정본인부담률** |
| 가운데 줄들 | 본인부담률이 다른 항목 금액 (식대 · 회송료 · 특수검사 …) | 그 금액 × 그 항목의 부담률 |
| 맨 아래 | 산정대상 금액 = 총진료비 − 제외 항목 금액 | 본인부담 합계 → 절사 → **본인부담금** · 청구액 |

첫 줄의 오른쪽 칸은 총진료비가 아니라 **맨 아래 산정대상 금액**에 법정률을 곱한 값이다
(계산지가 그렇게 생겼다 — 칸 아래에 `1,146,390 × 14%` 처럼 근거를 같이 적어 준다).
「제외 항목 합계」 줄은 사용자 요청으로 지웠다(2026-08-21) — 합계는 오른쪽 요약 카드에 남아 있다.

- **부담률은 전부 사람이 적는다. 규칙표와 그걸 쓰던 코드는 지웠다**(2026-08-21 요청 —
  조건 칸을 걷어낸 뒤로 "규칙값"을 고를 데가 없어 이름만 남아 있었다). 지운 것:
  `QUALS`·`INSTS`·`MODES`·`MG_TIER`·`HI_OUT`·`HI_IN`·`CS2_*`·`CS1_IN`·`MG*_OUT`·`MG_IN`·
  `SPECIALS`·`CALC_ITEMS` 와 `isHI/isCS2/isMG/outRateOf`·`typeTable`·`baseBurden`·`seniorBand`·
  `autoBase`·`applyAutoBase`·`renderHint`·`syncCalcInputs`·`itemDefsFor`·`defOf`,
  조건 칸(`#c-qual`·`#c-inst`·`#c-type`·`#c-spec`·`#c-dispense`·`#c-mode`)과
  「목록에서 항목 골라 넣기」(`#c-add`)·「부담률 규칙값으로」(`#c-restore`), `baseTouched`.
  → 자격·종별별 본인부담률은 **① 「본인부담금 규칙」 화면**(`data/burden-hira.js`)에서 본다.
  지운 코드가 다시 필요하면 깃 이력(2026-08-21 이전 판 `js/page-calc.js`)에 그대로 있다.
- **절사는 하지 않는다**(2026-08-21 요청 — 사용자가 알아서 한다). 절사 줄과 절사 단위 선택
  (`CUTS`·`calc.cut`)을 지웠고, **본인부담 합계가 그대로 본인부담금**이다(소수점까지 보여 준다).
  파랑 강조는 그 합계 칸 하나에만 붙는다. 세부작성요령 예시와 맞춰 볼 때는
  외래 100원 · 입원 10원 미만을 직접 버려야 한다(25,692 → 25,600).
- **본인부담 칸을 두 번 누르면 그 줄 본인부담을 손으로 적을 수 있다**(`data-fixkey` · `commitFix()`).
  적어 넣은 값은 `baseFix` · `items[].burdenFix` 에 담기고 곱셈 결과를 대신하며 칸에 「수기」라고
  적힌다. 비우고 나가면 다시 자동 계산이다.
- 부담률 칸의 **`%` ⇄ `원` 단추**가 정액으로 바꾼다(의료급여 외래 정액처럼 정액을 적을 때).
- 제외 항목은 **맨 아래에 빈 줄이 늘 한 개** 있고(`ensureBlankRow()`), 그 줄에 뭐든 적으면
  아래에 빈 줄이 또 생긴다(`isBlankItem()` · 표를 다시 그리지 않고 `<tr>` 만 붙인다).
  빈 줄의 **부담률은 채워 넣지 않는다**(`rate:null`) — 사용자가 직접 적는다.
- **원장 표는 720px 로 좁혀 두고 MG·병원 칸을 그 옆(24px 띄고)에 붙였다**(2026-08-21 요청).
  `.calc-left{flex:0 1 720px}` · `.calc-wrap{gap:24px}` 이고, 창이 1240px 이하면 아래로 접힌다.
  남는 오른쪽 공백은 그대로 둔다.
- **쓰는 법 안내는 카드 안에 넣지 않는다** — 표 아래 공백에 글자로만 둔다(`.calc-help`).
  「법정본인부담을 손으로 고쳤습니다」 경고는 지웠다(고친 칸에 「수기」라고 적히니 겹친다).
- **계산기 표도 열 너비를 끌어 조절한다**(다른 화면과 같다). 표가 안 줄어들고 옆 카드와 겹쳐
  보였던 원인은 `data/colw-defaults.js` 에 굳어 있던 옛 값 `"page-calc#0#5": [216,163,107,127,581]`
  이었다 — 표가 1,194px 이던 때 「열 너비 기본값으로 굳히기」로 잡힌 값이라 마지막(✕) 열이
  절반을 차지했다. **그 줄을 지웠다**. 계산기 표를 다시 굳히려면 폭을 맞춰 둔 상태에서 눌러야 한다.
  손잡이를 두 번 누르면(저장값 삭제) `renderLed()` 를 다시 돌려 소스 기본값
  (금액 150 · 부담률 118 · 본인부담 150 · ✕ 40px)으로 돌아온다.
- 비교표의 색 클래스 이름은 `.cmp-less` · `.cmp-more` 다 — `.more` 는 이미 「더보기」 단추가
  쓰는 이름(파랑 + **밑줄** + 12px)이라 그대로 쓰면 숫자에 밑줄이 그어졌다.
- **파랑 강조(`.strong`)는 최종 본인부담금 한 칸에만** 쓴다(2026-08-21 요청). 산정대상 금액 ·
  본인부담 합계 · 비교표 값은 굵은 본문색(`.num.b`), 청구액 줄은 강조 없이 둔다.
- **Tab · Enter 순서는 금액 → 같은 줄 부담률 → 다음 줄 금액**이다(`nextCell()`). 금액→부담률은
  Tab 이면 브라우저 기본 순서를 그대로 쓰고, 부담률→다음 줄 금액과 Enter 는 `keydown` 에서
  가로채 옮긴다 — ✕ 단추와 총진료비 줄의 `%`/`원` 단추는 건너뛴다.
- **금액 칸에서 셈이 된다** — `190040+342080` → 532,120. `calcExpr()` 이 `+ − × ÷` 네 가지만
  받고(괄호 없음, `eval` 안 씀) 곱하기·나누기를 먼저 접는다. 식을 치는 동안에는 글자를 손대지 않고
  값만 계산해 아래 합계에 반영하고, 칸을 떠나거나 Enter 를 누르면 계산 결과로 바꿔 적는다
  (`commitMoney()`). `190040+` 처럼 덜 적힌 식은 앞서 계산한 값을 지킨다.
- **적어 둔 것은 `localStorage['samguide_calc']` 에 남는다**(`saveCalc()` 를 `paint()` 끝에서
  호출 — 글자 하나 칠 때마다 저장). 새로고침·화면 이동 후 `loadCalc()` 가 되살린다.
  예전 판 자료도 받는다 — 진료형태(`mode`)가 있던 자료는 `입원 → 10원 · 외래 → 100원` 으로
  절사 단위를 옮기고, 목록에서 고른 줄은 이름 없는 줄로 들어온다(금액·부담률은 그대로).
  「비우기」를 누르면 그 탭만 빈 상태가 된다.
- 입력칸이 표 안에 있으므로 **글자를 칠 때마다 표를 다시 그리지 않는다**(커서가 빠진다).
  `paint()` 가 `[data-out]` 칸만 갈아 넣고, 줄이 늘거나 줄 때만 `renderLed()` 로 다시 그린다.
- 계산 방식은 대분류 칩(`.chips-seg`) 두 개 — **수기 계산** · **SAM 파일 불러오기**.
  SAM 쪽은 아직 안내문만 있다. 어느 레코드의 어느 금액을 읽을지 정해지면 그 칸에 붙인다.

### 계산 탭 — 명세서 여러 건 동시에 (`#c-tabs`, 2026-08-21)

계산 한 벌이 탭 하나다. 둘째 줄 칩(`.chips-rec`)으로 오가고 「+ 새 계산」이 빈 벌을 만든다.

- 상태는 `sheets[]` 배열이고 `cur` 이 지금 보는 벌, **`calc` 는 늘 `sheets[cur]` 를 가리킨다**
  (`let calc` — 그래서 나머지 코드는 예전처럼 `calc.` 만 본다). `switchSheet/addSheet/closeSheet`
  가 `calc` 를 바꿔 끼우고 `refreshCalc()` 로 화면을 다시 그린다.
- 탭 이름은 `계산 N` 이고 그 벌의 **총진료비**를 작게 붙여 구분한다(`[data-tab-total]` — `paint()`
  가 지금 탭의 값만 갈아 넣는다). ✕ 는 두 벌 이상일 때만 나오고 마지막 한 벌은 못 닫는다.
- 계산 방식(수기/SAM)은 탭과 상관없이 하나라 `calcWay` 로 따로 뺐다. SAM 쪽을 보면 탭 줄을 숨긴다.
- 저장 형식이 바뀌었다 — `localStorage['samguide_calc'] = {v:2, way, cur, sheets:[…]}`.
  탭이 없던 예전 자료(v1, 낱개 객체)는 `loadCalc()` 이 **첫 탭으로 옮겨 담는다**(자료를 버리지 않는다).

MG · 병원 비교표는 **탭마다 따로** 있다(`sheets[i].cmp`).

### 오른쪽 칸 — 날짜 계산기 (`#d-out`, 2026-08-21)

진료개시일에 입(내)원일수를 더해 **진료기간**을 알려 준다 — 입(내)원일수는 **양일법**이라
입원한 날이 1일이고 `진료종료일 = 진료개시일 + (일수 − 1)` 이다
(청구방법 237쪽 예시 「1월 1일~1월 5일 입원, 입원일수 5일」과 같은 셈).
요일도 같이 보여 준다.

**날짜는 아무렇게나 적어도 CCYY-MM-DD 로 바뀐다**(엑셀처럼, `dcNorm()`) —
`7/27` · `7.27` · `727` · `0727` 은 올해로, `20260727` · `2026-7-27` · `260727`(두 자리 연도는 2000년대)은
그 날짜로 읽는다. 13월·2월 30일처럼 없는 날짜는 **빨간 안내**만 띄우고 적은 글자를 지우지 않는다
(지우면 어디가 틀렸는지 볼 수 없다). 칸이 비어 있을 때만 저장값을 되살린다.
연속 입원 기준이라 날짜가 떨어진 외래에는 그대로 쓸 수 없다 — 화면에도 그렇게 적어 두었다.
값(`dateCalc`)은 계산 탭과 무관한 딸림 도구라 `localStorage['samguide_calc'].dates` 에 따로 담는다.
검산: 2026-01-01 + 5일 → 01.01(목)~01.05(월) · 1일 → 같은 날 · 1/30 + 5일 → 2/3 ·
2028-02-27 + 4일 → 3/1(윤년).

### 오른쪽 칸 — MG · 병원 두 벌 비교 (`#c-cmp`)

조건 칸이 있던 자리에 넣은 작은 표다(`table.fields.items.cmp`). 사용자 계산지의 오른쪽 표와 같다.

`CALC_ITEMS`)에 그대로 있다 — 화면만 바꿨다. 검산: 상급종합 28,800원 · 진찰료 21,030원
→ 본인부담 25,600원 / 청구 3,200원, 계산지 예 1,296,210원 · 식대 149,820원(50%) · 법정 14%

| 키 | 하는 일 |

지침 PDF 은 **글자를 그대로 뽑을 수 없다.** 폰트가 `Adobe-Korea1` CID 인데 유니코드 대응표
(ToUnicode)가 없어서 xpdf `pdftotext`(`-layout` · `-table` 둘 다) · 한글 · Word 변환이 모두
깨진 글자만 내놓는다. 그래서 처음에는 쪽을 **그림으로 그려서** 읽었다 — 이 PC 에는
poppler(`pdftoppm`) · ghostscript · ImageMagick 이 없어서 윈도우 자체 PDF 엔진
(WinRT `Windows.Data.Pdf`)을 파워셸로 불러 쪽마다 PNG 로 뽑았다(계산식 · 별표3 · 별표9 확인).

그런데 깨지는 방식이 **글리프 하나 → 글자 하나 일대일 치환**이었다. 그래서 대응표를 만들어
되살렸다(`tools/ndrg-scores.ps1`). 58쪽 1,850줄을 손으로 옮겨 적지 않았다.

| 무엇 | 어떻게 대응표를 정했나 |
|---|---|
| 숫자 `0~9` · `,` · `.` | PDF 221쪽(지침 215쪽)을 그림으로 읽은 값과 글자를 맞춰 봤다. `T`=0 `L`=1 `V`=2 `Z`=3 `a`=4 `b`=5 `i`=6 `h`=7 `k`=8 `m`=9 `B`=`,` `¹`(U+00B9)=`.` |

### 질병군번호로 채우기

### 계산 순서

① 총액 → ② 본인부담금 → ③ 열외군 → ④ 합계.

- **포괄수가** = `기준수가 + (환자 입원일수 − 평균 입원일수) × 일당수가 − 인공수정체 제외금액`,
  **10원 미만 4사5입**. 기준수가·일당수가는 `10원미만 4사5입(점수 × 조정계수 × 점수당 단가)` 이고
  점수당 단가는 **83.8**(39쪽 예시), 조정계수는 시범기관별·질병군별로 부여된 값이다(화면에서 적는다).
  인공수정체는 수정체 수술 질병군(C051~C054)에서 인공수정체를 쓰지 않거나 조절성(비급여)을 쓴 경우만 뺀다(35쪽 (다)).
- **인센티브포괄수가**(= 가산수가) = `포괄수가 × 정책가산율 총합`, **10원 미만 절사**.
- **비포괄수가**는 직접 적는다(10원 미만 절사 없음). **적는 칸이 두 군데**인데 같은 값이다 —
  총액 표의 「비포괄수가」 줄(`#nd-np-total`)과 비포괄수가 원장의 「비포괄수가 총액」
  (`[data-nx="total"]`). 어느 쪽에 적어도 `ndSyncNpTotal()` 이 다른 쪽 글자를 맞춘다
  (2026-08-24 요청). 지금 치고 있는 칸은 건드리지 않는다 — 셈(`6540*4*4`)을 적는 중일 수 있다.
  비포괄 항목은 행위별수가의 **80%**,
  전액비포괄 항목은 **100%** 로 산정한 금액이다(35쪽). 부담률이 다른 줄(전액비포괄 · 식대 …)은
  ② 계산기 · 질병군 계산기와 같은 **원장**으로 나눠 적는다.
- **신포괄총액** = 세 가지를 더한 뒤 **10원 미만 절사**.
- **본인부담금**(37쪽 · 38쪽 그림3) — 둘 중 하나를 자동으로 고른다.
  - **가)** 입원일수 ≤ 평균 입원일수, 또는 **정신과 14개 질병군(U010~V610)**(입원일수와 무관):
    `(포괄수가 + 비포괄수가) × 20%`
  - **나)** 입원일수 > 평균 입원일수:
    `① 기준수가 × 20%` + `② (입원일수 − 평균 입원일수) × 일당수가 × 23%` + `비포괄수가 × 20%`
  - **가산수가(인센티브)에는 본인부담이 붙지 않는다** — 지침의 두 식에 포괄수가·비포괄수가만 있고,
    보험자부담금은 `총액 − 본인부담금` 이다(39쪽 마).
  - 마지막에 **10원 미만 절사** — 39쪽 예시가 `315,746 + 28,369.212 = 344,115.212 → 344,110원` 이다.
  - 의료급여 · 전액비포괄 항목은 행위별수가제와 같은 부담률을 쓴다(37쪽 ※) → 조건 줄의
    **부담률 / 초과분** 칸이나 원장의 줄별 부담률로 고친다.
  - 제외금액은 나) 에서 `(기준수가 − 제외금액) × 20%` 로 넣는다 — 제외금액은 포괄수가에서 빠지는
    금액이고 포괄수가의 고정분이 기준수가라, 가) 와 값이 어긋나지 않게 이렇게 맞췄다.
- **열외군**(36쪽 (5), 37쪽 (다)): 신포괄총액이 **정상군 입원기간 행위별 총진료비**보다 적고
  그 차액이 **200만원을 초과**할 때만 열외군.
  총액 = `신포괄총액 + (행위별 총진료비 − 신포괄총액 − 200만원)`,
  본인부담 = `위 본인부담 + (행위별 총진료비 − 신포괄총액 − 200만원) × 20%`.
  행위별 총진료비는 신포괄에서 급여지만 행위별에서 비급여인 행위는 관행수가, 약제·치료재료는
  실구입금액으로 계산한 금액을 적는다.

### 중증도 한 자리를 왜 안 내나

기타진단별 중증도 점수 **(부표 1)** 는 분류집에 있다(`KDRG_CCL`, 3,861건).
AADRG별 중증도 구분 기준 **(부표 2)** 도 있다(`KDRG_SEV`, 860건 · DRG 2,040개).
없는 것은 **CC edit** — 주진단과 관련이 높은 기타진단의 점수를 0 으로 내리는 규정이다.
책 1173쪽에 「매우 복잡하기 때문에 전산적인 처리가 필요하며 본 책자에는 포함시키지 않았다」고 적혀 있다.

그래서 화면은 ⓐ 부표2 의 **6자리 후보**를 늘어놓고, ⓑ CC edit 을 적용하기 **전** PCCL 을 참고로 보여 주며
(실제보다 높게 나올 수 있다), ⓒ 대조는 **앞 5자리(AADRG)** 로만 한다.

PCCL 식은 책 1173쪽 그대로다 — `α=0.4`, `k = P01~P67 이면 1, 나머지 2`,
`x = round( ln(1+Σ CCL(i)·exp(-α(i-k))) / (ln(3/α)/4) )`, 4 를 넘으면 4.

### MDC 를 고를 때 조심한 것

주진단 하나가 여러 MDC 목록에 드는 것이 14,101 중 2,007건인데 거의 전부 두 가지다.

  표 세 개를 나눠 두고(`KDRG_HIV`) 그 조건이 맞을 때만 MDC 18-1 로 본다.
- **MDC 21-1(다발성 외상)** — 1,721건 전부가 다른 MDC 에도 있다. 「서로 다른 신체부위」의 중요 외상이

### 데이터 다시 만드는 법

```bash
pdftotext -table -enc UTF-8 "KDRG 분류집 (신포괄지불제도용 Version 1.6).pdf" kdrg.txt
LC_ALL=C.UTF-8 awk -f tools/kdrg.awk kdrg.txt > kdrg.jsonl
LC_ALL=C.UTF-8 awk -v OUT=data -f tools/kdrg-js.awk kdrg.jsonl
```

- **`-layout` 이 아니라 `-table` 이다.** `-layout` 은 보험코드 칸이 두 줄씩 밀려 엉뚱한 시술코드와
  짝지어진다(자555 ↔ S5572 처럼). `-table` 은 칸을 지킨다.
- `LC_ALL=C.UTF-8` 없이 돌리면 awk 가 글자를 바이트로 세어 칸 위치가 어긋난다.
- 쪽 범위는 `tools/kdrg.awk` 의 `BEGIN` 에 있다(ADRG 목록 25~55 · 본문 57~1176 · 우선순위 1179~1192 ·
  부표1 1197~1218 · 부표2 1219~). **판이 바뀌면 여기만 고친다.**
- 여백에 세로로 박힌 장식(`MDC` · `01` · `(B)` · `KDRG` · 쪽번호)이 본문 줄 앞뒤에 붙어 나온다.
  `fields()` 가 2칸 이상 공백으로 칸을 나눈 뒤 앞뒤의 장식 칸만 걷어낸다.
  **칸 안에서 여러 칸 벌어진 공백은 한 칸으로 줄인다** — PDF 조판 자국이고 원문에는 없는 공백이다.
- MDC 구분면 뒤의 대여섯 쪽은 **분류 흐름도 그림**이라 글자가 없다(185쪽). 그림이 보여 주는 조건
  (`Age >18` 등)은 질병군 이름과 정의식에 그대로 있어 빠뜨리는 규칙은 없다.

`js/page-samcheck.js`. 청구 파일을 끌어다 놓으면 **서식번호를 읽어** 레이아웃을 찾고,
**줄마다 바이트 길이**가 그 서식과 맞는지 본다. 데이터 파일이 없다 — 규격을 전부

### 허용 길이를 어떻게 정하나

여기에 숫자를 적어 두지 않는다. 레이아웃에서 세 가지를 모아 집합으로 쓴다.

| 근거 | 예 |
|---|---|
| 전체 길이 = 필드 끝 위치의 최대값 | 의과 청구서(H) 2,096 · 일반내역(A) 348 |
| 맨 뒤 필드 설명에 `생략 허용` · `기재 허용` · `(옵션)` 이 적혀 있으면 그 앞까지도 허용 | H 의 참조란(1,750byte)을 뺀 346 · 진료내역(C) 의 치식 4칸을 뺀 204 |
| `registerClaimType` 의 `blankRowLen` | 진료내역(C) 204 |

그래서 의과 청구서는 `346 / 2096`, 진료내역은 `204 / 236` 이 맞는 길이다.
화면의 「허용 길이」 칸에 그 목록을 그대로 보여 주므로, 기준이 실제와 다르면 바로 눈에 띈다.

**옵션 필드 묶음은 통째로 있거나 없다** — 치식 4칸을 하나씩 떼어낸 중간 경계(212·220·228)는
만들지 않는다. 실샘플에서 진료내역 708줄이 모두 236byte 였고, 중간 경계를 허용하면 진단이
나빠진다 — 231byte 를 "236 에서 **5byte 모자람**"이 아니라 "228 에 3byte 더 붙음"으로 읽는다.

### 레코드를 어떻게 가려내나

줄 하나마다 **서식번호 → 내역구분 → 파일명 → 길이** 순서로 본다.

- **서식번호** — 청구서(H)·일반내역(A)에만 있다. 위치가 분야마다 다르다(의과 17, 의료급여정액·한방·산재 16, 자보 청구서 19).
  레이아웃에서 `서식번호` 필드를 찾아 그 자리 값이 코드표에 있는지만 본다.
- **내역구분** — 의과·DRG·신포괄·자보·완화는 위치 16 에 `A`~`F` 가 있어 한 파일에 여러 레코드가 섞여도 갈린다.
- **파일명** — 내역구분이 없는 분야(의료급여정액 `H040.n` · 한방/첩약 `K020.n` · 산재 `M020.n`/`M021.n` · 자보한방 `C110.n`)는
  파일 하나가 레코드 하나다. 파일명 판별은 `js/layout-*.js` 의 `*RoleForFilename` 을 그대로 부른다 — 규칙을 여기에 다시 적지 않는다.
- **길이** — 위 셋이 다 안 되면 길이가 딱 하나 맞는 레코드로 본다.

청구분야는 파일명(그 분야만 쓰는 이름이면 큰 점수) · 서식번호 · 내역구분 · 길이로 점수를 매겨 고르고,
청구서의 **진료형태**가 `formTypeChars` 에 걸리면 그쪽을 우선한다(완화 `B`/`C` · 신포괄 `P` — 서식번호가 H010 하나라 이것 말고는 GEN 과 갈릴 근거가 없다).
짐작은 짐작이라 **대분류 칩으로 직접 바꿀 수 있다.** 한방과 첩약처럼 파일명·서식번호가 완전히 같은 짝은 길이 분포로 갈린다.

### 파일 구조 점검 (2026-08-21)

길이가 다 맞아도 파일 짜임새가 틀릴 수 있다. 두 가지를 본다.

| 규칙 | 뜻 |
|---|---|
| **청구서(H)는 파일에 1줄** | 청구 두 건을 한 파일에 이어 붙이면 걸린다. 두 번째 이후 H 줄에 오류를 붙인다 |
| **청구서의 「건수」 = 일반내역(A) 줄 수** | 건수는 "명세서 청구건수 합"이다. 청구서가 1줄이고 일반내역이 함께 첨부된 때만 본다 |

실샘플 `53649_20180506_2026041210_B21.GHP`(2026-08-21, 사용자 제공)이 바로 이 경우였다 —
H010 이 **2줄**(건수 1건/3건 · 청구일자 20260805/20260812)이고 일반내역이 4줄이었다.
길이는 전부 정상이라 길이 점검만으로는 안 걸린다.

이 샘플로 허용 길이도 대조했다 — **H 2,096 · A 348 · B 78 · C 236 · E 739** 로 화면 기준과 완전히 일치.
진료내역(C)의 치식 4칸은 실제로 늘 들어오고(236), 특정내역(E)은 700byte 를 꽉 채워 온다(739).

### 무엇을 알려주나

- 파일마다 — 크기 · 줄 수 · 줄바꿈(CRLF/LF/없음/섞임) · **읽어낸 서식번호와 그 뜻** · 레코드 구성 · **길이 분포**
- 어긋난 줄마다 — **명일련번호 · 수진자 이름**, 몇 byte 모자란지/남는지, **어느 필드에서 끊겼는지**, 빠진 필드 목록, 뒤에 남은 값
  - 이름은 **일반내역(A)에만** 있어서, 같은 `청구번호 + 명일련번호` 의 A 줄에서 가져온다(명세서 파일이 따로 오는 분야도 있어 파일을 가로질러 찾는다).
    필드 이름이 분야마다 달라(수진자성함 · 수진자성명 · 산재근로자성명 · 환자성명) `layout-shim.js` 의 `PATIENT_NAME_FIELDS` 로 찾는다.
  - 레코드를 판별하지 못한 줄은 표준 앞머리(청구번호 1~10 · 명일련번호 11~15)로 읽고 그렇게 적어 준다.
    11분야 모두 이 자리가 같아서 쓸 수 있다(`spec.detailHead` — 한 분야라도 다르면 안 쓴다).
- 줄을 누르면 팝업이 떠서 **파일을 그대로** 그 줄로 옮겨 보여 준다(아래 「파일 그대로 보기 팝업」).
  같은 팝업의 「필드별로」 는 줄을 **필드별로 잘라서** 보여 주고, 끊긴 칸과 숫자 칸에 숫자가 아닌 값이 든 칸을 짚는다
  (첫 번째가 줄이 밀린 자리일 때가 많다 — **짐작이라고 적어 둔다**)
- 파일 단위 경고 — BOM(3byte) · **UTF-8 로 저장**(한글이 3byte 가 되어 길이가 어긋난다) · 줄바꿈 섞임 · 빈 줄
- 줄바꿈이 없는 파일은 레코드 길이로 나누어떨어지면 **고정길이로 잘라서** 본다

### 어긋난 줄을 누르면 — 파일 그대로 보기 팝업 (2026-08-21 사용자 요청)

줄을 누르면 팝업이 뜨고 **파일을 그대로** 그 줄로 옮겨 보여 준다. SamGuide 의 첫 모달이다
(`#sc-modal`, `.page` 안에 두면 화면 전환에 같이 숨으므로 `#app` 밖에 둔다).

- 머리에 파일명 · `N줄 / 전체 M줄` · 길이 · 레코드와 허용 길이 · **명일련 · 수진자** · 오류 문구.
- 소분류 칩 두 개 — **파일 그대로** · **필드별로**(전에는 표 아래에 펼쳐 보여 주던 것을 여기로 옮겼다).
- **이전 / 다음** 은 표에 뜬 것과 같은 순서의 어긋난 줄 목록을 따라간다(`Shift`+`←` `→`). `Esc` 로 닫는다.
  줄 번호를 적고 Enter 를 누르면 그 줄로 간다 — 창 밖이면 그 줄을 가운데 두고 창을 다시 잡는다.
  방향키로 돌아다니다 목록에 없는 줄에 있으면, 그 줄을 기준으로 바로 앞/뒤의 어긋난 줄로 간다.
- 어긋난 자리를 줄 안에 표시한다 — 짧으면 끝에 `여기서 끊김 · N byte 모자람`,
  길면 서식에 없는 꼬리를 테두리로 두른다(`<mark>`).

### 바이트 자리 알려 주기 (2026-08-21 사용자 요청)

머리 아래 띠(`#sc-pos`)에 **몇 줄 몇 byte 인지 · 그 자리가 어느 필드인지 · 그 필드의 몇 번째 byte 인지 ·
그 필드에 든 값**을 적는다. 필드 밖이면 「서식에 없는 자리」, 줄이 끊겨 필드가 덜 왔으면 그것도 적는다.

| 하는 법 | 무엇 |
|---|---|
| **커서를 갖다 대면** | 그 자리를 바로 알려 준다 (줄을 옮겨 다니지 않아도 된다) |
| **`←` `→`** | 바이트 커서를 한 byte 씩 옮긴다 |
| **`Ctrl`+`←` `→`** | 필드 경계로 건너뛴다 |
| **`Home` `End`** | 줄의 처음 · 끝으로 |
| **`↑` `↓`** | 앞뒤 줄로 (바이트 자리는 그대로 두고 줄 길이에 맞춰 자른다) |
| **줄을 누르면** | 누른 자리로 커서가 간다 |

팝업을 열면 커서가 **어긋난 자리에 먼저 놓인다** — 짧으면 끊긴 마지막 byte, 길면 서식에 없는 첫 byte.
커서가 있는 byte 는 파랗게 채우고(`.car`), 그 byte 가 든 필드 범위는 밑줄로 묶는다(`.fld`).

**바이트 자리와 글자 자리는 다르다** — EUC-KR 은 한글이 2byte 다. 화면에서 커서가 짚는 것은 글자이고
알려 줘야 하는 것은 바이트라, 줄마다 「글자 i 의 첫 바이트 자리」를 만들어 둔다(`scMapOf`).
CP949 규칙(`0x00~0x7F` 는 1byte 한 글자, `0x81~0xFE` 로 시작하면 2byte 한 글자)으로 훑고
**`TextDecoder` 가 낸 글자 수와 맞는지 확인한다** — 어긋나면 「바이트 자리를 셀 수 없습니다」로 알린다.
(검증: 수진자성함이 106byte 부터인 348byte 일반내역에서 `홍`=106 · `길`=108 · `동`=110, 345글자/348byte.)

`caretPositionFromPoint` 는 **글자 사이** 자리를 주므로 글자의 오른쪽 절반을 짚으면 다음 글자 번호가 온다.
앞 글자의 사각형에 그 점이 들어 있으면 앞 글자로 되돌린다 — 그래야 글자 어느 쪽을 짚어도 같은 byte 가 나온다.

커서 알림은 `requestAnimationFrame` 으로 묶지 않는다 — **창이 화면에 없으면 콜백이 오지 않아 값이 멈춘다**
(2026-08-21 에 실제로 이걸로 한 번 헛짚었다). `performance.now()` 로 16ms 간격만 둔다.

**파일 전체를 한 번에 그리지 않는다.** 그 줄 앞뒤 60줄만 그리고 「더 보기」로 200줄씩 넓힌다
(실샘플 규모 396KB · 1,046줄에서 점검 26ms · 팝업 30ms). 줄마다 2,096byte 짜리가 섞여 있어
전부 그리면 화면이 멎는다.

기본은 칸 안에서 접어 보여 주고, 「한 줄로」를 누르면 **그 상자 안에서만** 좌우로 움직인다
(`.sc-raw.nowrap{overflow-x:auto}` + 줄번호 칸 `position:sticky`). 페이지에는 가로 스크롤이 생기지 않는다.

색은 새로 만들지 않았다 — 빨강은 `--minus` 하나뿐이라 어긋난 바이트는 **칠하지 않고 테두리**로
두르고 꼬리표만 `--minus` 로 채웠다. 어둡게 덮는 막(`.sc-modal-scrim`)만 `--text` 의 rgba 45% 다
(`--shadow` · `--focus` 가 이미 쓰는 방식).

## 산정특례 데이터 다시 만드는 법

「산정특례_질환별_등록기준」 엑셀은 **시트마다 열 배치가 다르다.**

```bash
LC_ALL=C.UTF-8 awk -f tools/special.awk special.tsv > out.json
```

로 바꿔 `data/special-codes.js` 에 넣는다. 상병일련번호는 엑셀에서 숫자로 읽히는 경우가 있어
자릿수를 맞춰 0을 채워야 한다(대부분 2자리, 극희귀·기타염색체이상질환은 3자리).

### 적용일자·종료일자와 「지난 기호」 흐리게 (2026-08-24 사용자 지정)

⑥ 화면 표는 **구분 · 특정기호 · 상병코드 · 상병일련번호 · 질환명 · 적용일자 · 종료일자** 일곱 칸이다.
날짜는 질환명 **오른쪽**에 둔다(2026-08-24 요청 — 코드·상병을 먼저 보고 날짜는 마지막에 확인한다).
날짜는 행마다 다른 값이 아니라 **기호마다 하나**라서 `SPECIAL_CODES` 에 넣지 않고
`js/page-special.js` 의 `spFrom()`·`spTo()` 가 `SYMBOLS` 에서 찾아 쓴다(등록기준 데이터는 그대로 둔다).

- 종료일자가 **오늘보다 지난** 기호는 줄을 지우지 않고 **글자만 흐리게**(`tr.sp-past`, `--text-4`) 죽인다.
  지난 청구를 들여다볼 때 그 기호가 언제까지 살아 있었는지 봐야 하기 때문이다.
  오늘은 `SP_TODAY` 가 `new Date()` 로 만들고, 날짜가 `CCYY-MM-DD` 라 글자 비교가 곧 날짜 비교다.
  종료일자가 **오늘이면 아직 살아 있는 것**으로 본다(`<` 로 비교).
- 검색 하이라이트(`mark`)는 흐린 줄에서도 색을 그대로 둬서 찾은 자리가 보이게 했다.
- 아직 끝나지 않은 기호는 원본대로 `9999-12-31` 을 적는다("현재" 로 바꾸지 않았다 — 원본 값이다).
- 검색은 날짜도 걸린다 — `2024-03-31` 이나 `2017` 로 찾으면 그 무렵 끝난 기호가 나온다.

### F 기호 명칭의 하이라이트 (`SP_F_KEY`, 2026-08-21 사용자 지정)

F 기호 명칭은 대부분 「국민건강보험법 시행령」 조문 인용이라 길다. 그래서 **눈으로 먼저 찾는 문구만**
파랑 볼드(`.sp-key`)로 띄운다. 검색 하이라이트(`mark`, 연파랑 배경)와 헷갈리지 않게 **배경은 주지 않는다.**

- 문구는 명칭 **원문에서 그대로 잘라낸 것**이고, 표에 찍히는 글자는 원문 그대로다(감싸기만 한다).
- **F007** 은 사용자가 "정신의학과"로 적었지만 원문이 "정신건강의학과 입원진료"라 원문 글자를 쓴다.
- **F025·F026** 은 문구가 떨어진 두 군데다 — "상급종합병원" + "외래 재진/초진 진료".
- **F006**(요양병원 입원 본인부담율 40% 적용환자)만 지정이 없어 하이라이트가 없다.
- **F022** 는 명칭 뒤에 회색 작은 글씨(`.sp-keynote`)로 "국가건강검진 시 시행한 보건복지부 장관이
  정하여 고시하는 확진검사"를 덧붙인다. 이건 **고시 원문이 아니라 화면 설명**이라 `SP_F_NOTE` 에 따로 뒀다.
- 문구를 명칭에서 못 찾으면 콘솔에 경고가 찍힌다 — 특정기호 엑셀을 갈아 끼워 문구가 바뀌면 바로 드러난다.

**칩 순서는 건수 순이 아니다** (`SP_HEAD_ORDER`, 2026-08-21 사용자 지정).
`전체` 다음 다섯 개를 못 박고 — **F코드 · 이식·공여자 · 가정간호 · 희귀질환 · 중증난치질환** —
나머지는 **건수 많은 순**(암 → 극희귀질환 → 결핵 → 기타염색체이상질환 → 중증치매 → 기타 V코드 →
중증질환 → 중증화상 → 잠복결핵)이다. 건수가 같으면 원래 순서를 지킨다.
자주 보는 구분을 앞에 두려는 것이니, 순서를 바꿀 때는 `SP_HEAD_ORDER` 만 고친다.

이 구분들의 **상병코드·상병일련번호는 원본에 없는 값이라 `—`** 로 비운다(추측해 채우지 않는다).
질환명 칸에는 특정기호 목록의 한글명칭을 원문 그대로 넣고, 종료된 기호만 `(~종료일자)` 를 덧붙인다.
새 「특정기호_YYYYMMDD.xlsx」로 `data/symbol-codes.js` 를 갈아 끼우면 이 구분들도 같이 따라간다.
배정해 둔 기호가 목록에서 사라지거나 등록기준으로 옮겨가면 콘솔에 경고가 찍힌다(조용히 흘리지 않는다).

**구분을 안 고른 「전체」는 특정기호 오름차순**으로 정렬한다(F001 → … → V999).
구분을 고르면 등록기준 엑셀 순서를 그대로 둔다.

## 약국 산정특례 데이터 다시 만드는 법

원본은 「본인일부부담금 산정특례에 관한 기준」 **[별표 6]** — 약국 요양급여비용총액의
본인부담률 산정특례 대상 (제6조 관련) 이고, 받은 파일은 **hwpx** 다.

hwpx 는 zip 안에 XML 이 든 형식이라 **한글(HWP) COM 을 띄우지 않고 그대로 읽을 수 있다**
(이 PC 에서 HWP COM 은 한컴 보안 대화상자에서 멈춘다 — CLAUDE.md 참조). PDF 로 바꿔 달라고
할 필요가 없다.

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/pharm.ps1 "경로/[별표 6] ….hwpx"
```

`data/pharm-codes.js` 를 새로 쓴다(304행 · 본문 6문단). 스크립트가 하는 일은 두 가지다.

- `Contents/section0.xml` 의 첫 `hp:tbl` 에서 **구분 · 대상 · 특정기호** 3열을 읽는다.
  원문은 구분·특정기호가 **병합 셀(rowSpan)** 이라 값이 묶음의 첫 행에만 있다 —
  "앞의 값 이어받기" 로 풀어 행마다 값을 채운다.
- 표 앞 문단에서 **1호**(상급종합 50% · 종합병원 40%)와 **2호**(V100 으로 제외하는 경우,
  가·나·1)·2\)) 를 뽑아 `PHARM_NOTES` 로 넣는다.

주의할 점 두 가지 — 둘 다 한 번씩 걸렸다.

- `.ps1` 파일은 **UTF-8 BOM** 으로 저장해야 한다. Windows PowerShell 5.1 은 BOM 없는 파일을
  시스템 ANSI 코드페이지로 읽어 한글 주석이 깨지고 파서 오류가 난다.
- XML 을 읽을 때 **`PreserveWhitespace = $true`** 가 필요하다. 원문은 줄이 바뀌는 자리의
  공백을 `<hp:t> </hp:t>` 별도 run 으로 넣어 두는데, 기본값이면 공백만 있는 노드가 버려져
  "조제받는경우" 처럼 낱말이 붙어 버린다.
- 파일명에 `[별표 6]` 대괄호가 들어 있어 `Copy-Item` · `Expand-Archive` 는
  **`-LiteralPath`** 로 넘긴다(대괄호를 와일드카드로 해석한다).

### 화면에서는 병합을 되살리지 않는다

원문 표는 구분 번호와 특정기호가 병합 셀로 묶여 있지만, 화면에서는 **행마다 그대로 적는다.**
걸러 보거나 검색해 행이 흩어졌을 때 빈 칸이 "위와 같음" 인지 "값 없음" 인지 헷갈리는데,
이건 심사 기준이라 헷갈릴 여지를 두지 않는다. 대상 칸의 상병코드는 원문처럼 질환명 뒤
괄호에 그대로 두고 열을 따로 만들지 않았다(검색은 그 글자에 걸린다).

특정기호는 ① 화면과 같은 배지(`.symb`)로 그린다 — 커서를 올리면 `data/symbol-codes.js` 의
한글명칭이 뜬다. 다만 이 표에서는 특정기호가 **맨 오른쪽 열**이라 말풍선(최대 360px)이
기본값(`left:0`)이면 화면을 넘어 **페이지에 가로 스크롤이 180px 생긴다.**
`.ph-sym .symb::after{left:auto; right:0}` 로 왼쪽으로 펴서 막았다.
카드에 `overflow` 를 걸어 잘라내는 방법은 쓰지 않는다 — 표 머리줄 고정이 깨진다.

필터는 특정기호 한 줄뿐이라 **대분류(`.chips-seg`)** 로 그린다(필터 두 줄 규칙).

## 응급의료행위 데이터 다시 만드는 법

원본은 수가책 **「건강보험 행위 급여･비급여 목록표 및 급여 상대가치점수」** PDF 의
**제1편 제2부 제19장 응급의료수가 — (별표 1) ~ (별표 4), 인쇄 쪽번호 709~763쪽**이다.

이 PDF 는 **인쇄 쪽번호 = PDF 쪽번호 − 13** 이라 709~763쪽은 PDF 722~776쪽이다.
(제19장이 시작하는 인쇄 695쪽이 PDF 708쪽인 것으로 확인했다. 판이 바뀌면 이 차이도 바뀐다 —
`pdftotext -layout -f <쪽> -l <쪽>` 로 쪽 아래 숫자를 보고 다시 재는 게 빠르다.)

```bash
pdftotext -table -enc UTF-8 -f 722 -l 776 수가책.pdf emg.txt
LC_ALL=C.UTF-8 awk -f tools/emergency.awk emg.txt > data/emergency-codes.js
```

- **`-table` 이어야 한다.** `-layout` 으로 뽑으면 왼쪽 열(장·분류번호·코드)과 오른쪽 열(분류)이
  줄 수가 달라 **한 칸씩 밀린다** — 실제로 `자31-1 골이식술 / 자31 (빈칸) / 자32가 골편절제술` 처럼
  나왔다. `-table` 로는 `자31-1 골이식술 / 자31 골편절제술 / 자32가 천두술(진단목적)` 로 맞는다.
- **`LC_ALL=C.UTF-8` 없으면 안 된다.** awk 의 `substr` 가 한글을 바이트로 세어 칸이 어긋난다.
- 윈도우 `pdftotext` 는 줄끝에 **CR**, 쪽끝에 **FF(쪽 나눔)** 을 넣는다. 지우지 않으면
  값 끝에 딸려 들어간다(`…[부신절제 포함]\f` 같은 값이 나왔다). awk 첫 규칙에서 지운다.

`data/emergency-codes.js` 를 새로 쓴다 — `EMG_TABLES`(별표 4개) · `EMG_CHAPTERS`(장 이름) ·
`EMG_CODES` 1,277행.

### 칸 안에서 접힌 줄 붙이기 — 규칙을 정해 두고 추측하지 않는다

원문 표는 칸 폭이 좁아 행위명이 여러 줄로 접히는데, **PDF 는 접힌 자리에 띄어쓰기가
있었는지 알려주지 않는다**(양쪽정렬이라 줄끝 공백은 아예 그려지지 않는다).
게다가 원문 자체가 일관되지 않다 — 같은 창상봉합술 계열에
`표재성인것,길이1.5cm미만` 과 `표재성인 것, 길이5.0cm이상` 이 함께 있다.

그래서 `tools/emergency.awk` 의 `glue()` 가 아래 규칙으로만 붙인다. 규칙을 벗어난 자리를
사람이 눈으로 메우지 않는다(추측으로 글자를 넣거나 빼지 않는다).

1. 양쪽정렬 때문에 늘어난 공백(2칸 이상)은 1칸으로 줄인다
   — `근육에달하는           것,` → `근육에달하는 것,`
2. 접힌 자리를 **붙여 쓴다**
   - 앞줄이 `- – ( [ ･ / ~ ∼` 로 끝날 때 — `…-비위관삽입에 의한 세척` + `-위출혈의 경우`
   - 뒷줄이 `) ] - – , ~ ∼ ･` 로 시작할 때
   - 뒷줄이 **소문자 알파벳**으로 시작할 때(낱말 중간에서 접힌 것) — `(C` + `ross-Clamping)`
   - 앞줄이 **숫자+단위**로 끝날 때 — `길이5.0cm` + `이상~7.5cm미만)`
   - 앞줄에 **띄어쓰기가 아예 없을 때**(붙여 쓴 행위명) — `…100ml∼500ml[1병또` + `는포장단위당]`
3. 그 밖에는 1칸 띄운다 — `…심방 또는 심실 전극을` + `삽입하는 경우)`

이 규칙으로 `ILA Membrane` + `Ventilator 사용`(띄움)과 `…상급종합병원･` + `종합병원`(붙임)이
둘 다 맞게 나온다.

원문 오탈자는 **그대로 옮긴다.** (별표 4) `자267나(2)` 는 여는 괄호만 있고 닫는 괄호가 없다
(`결장절제술(아전절제[…]-림프절청소포함하지 않는 것`) — 원문이 그렇다.

고정(sticky)하는 것은 사이드바와 **① 화면 표의 열 머리줄**이다. 툴바는 페이지와 같이 스크롤한다.
머리줄 고정은 2026-08-20 「표 가시성 개선 및 구조 재설계」 핸드오프가 요구한 것으로,
그 전 규칙("고정은 사이드바뿐")을 ① 화면에서만 뒤집었다. 자세한 것은 아래 표 디자인 절에.

**좌우 스크롤을 만들지 않는다 — SamGuide 전체 전제(2026-08-20).** 어떤 화면에서도 페이지에
가로 스크롤바가 생기면 안 된다. 표가 넓어지면 표를 넓히지 말고 칸 안에서 줄바꿈시킨다.
그래서 `td.rate` 와 `th` 의 `white-space:nowrap` 을 걷어냈고, 너비를 안 정한 표는
`width:max-content` 대신 **`table-layout:auto` + `width:100%`** 로 두어 카드를 넘지 않게 했다
(열은 여전히 내용에 맞춰 잡히고 균등분배되지 않는다). 건보 기타의 `비고` 열이 화면을 넘던 문제가
이것으로 해결됐다. 두 제도 모든 탭과 나머지 9개 화면을 훑어 페이지 가로 스크롤 0을 확인한다.

① 본인부담금 규칙 표는 **열을 균등분배하지 않는다.** 너비를 정한 표만
`table-layout:fixed` + `<th>` 인라인 `width` 이고(핸드오프 지정값), 나머지는 `width:100%` 다.
너비 없이 fixed 를 걸면 열이 균등분배되므로 절대 그렇게 하지 않는다.
칸 여백은 8px 16px, 열·행 구분선 1px, 묶음 경계 2px.
화면에서 감추는 열은 `B2_HIDE` 에 모아 둔다 — `근거`(시행령 조항)와 `끝수계산`.
끝수계산은 값이 전부 `10원 미만 절사` 라(입원명세서는 전체가 10원 미만 절사) 열을 둘 이유가 없어
2026-08-20 에 감추고, 그 값은 카드 제목 옆 보조문구(`B2_AUX`)로 옮겼다.
데이터(`data/burden-hira.js`)에는 두 열 다 그대로 남긴다.
rowSpan 으로 묶는 행 때문에 이어지는 행의 항목 칸이 DOM 상 첫 자식이 된다 — 열을 가리킬 때
`:first-child`·`:last-child` 를 믿을 수 없으므로 그리는 쪽에서 열 번호를 보고 클래스를 붙인다.

### 특정내역 — 표 한 장 (2026-08-21)

목록 + 상세 두 칸(메모장 구조)이던 화면을 **표 한 장**으로 바꿨다. 열은 세부작성요령 PDF 의
3단 표와 같게 **`구분코드 / 특정내역명 / 작성요령 및 기재형식`** 세 개다(8% · 17% · 75%).
너비 기본값은 `js/page-detail.js` 의 `DT_COLW`(% 로 적는다 — px 는 좁은 창에서 가로 스크롤을
만든다)를 `<th>` 인라인 `width` 로 넣는다. 머리줄 손잡이로 끌어 바꾼 값이 있으면 그쪽이 이긴다.

내역구분 · 기재형식 · 분야 · 적용기간 열은 2026-08-21 에 없앴다(사용자 요청).
남은 정보는 이렇게 옮겼다.

- **기재형식** — 세부작성요령 본문의 `♦ 기재형식:` 항목에 원래부터 들어 있다(114건 전부 확인).
  PDF 에 없는 코드는 통합본 값을 `기재형식: X(4)` 한 줄로 붙인다.
- **분야** — 작성요령 칸 **맨 마지막**에 선으로 갈라 배지로 넣는다(`.dt-fld`).
  PDF 에는 없는 통합본 값이라 원문 항목과 구분해 둔다.
- **내역구분** — 화면 표기는 없애고 소분류 필터(둘째 줄 pill)로만 쓴다.
- **적용기간** — 현재 판에는 표기하지 않는다. 지난 판만 구분코드 칸에
  `지난 판 ~2020.11.30` 배지로 남긴다(끝난 규칙을 현행으로 오해하지 않도록).

세부작성요령은 **접지 않는다** — 작성요령 칸에 원문 모양으로 펼쳐 둔다. PDF 에 없는 코드는
통합본의 작성요령을 쓰고, 칸 맨 위에 어느 원본에서 온 것인지 작게 적는다(`.dt-src`).

본문의 줄바꿈이 데이터에 `\n` **두 글자**로 들어와 있어 예전 상세 칸에는 `\n` 이 글자로 보였다.
원본 글자는 그대로 두고 그릴 때만 실제 줄바꿈으로 바꾼다(`dtBody()`).

### 메모장 — 표 한 장 (2026-08-21)

메모장도 목록 + 편집 두 칸 배치를 걷어내고 **다른 카테고리와 같은 표 한 장**으로 바꿨다
(사용자 요청 "메모장 표 형태로 보여줘"). 열은 **`제목 / 내용 / 수정`** 세 개다(22% · 62% · 16%).
너비 기본값은 `js/page-memo.js` 의 `MM_COLW`(% 로 적는다 — px 는 좁은 창에서 가로 스크롤을
만든다)를 `<th>` 인라인 `width` 로 넣고, 머리줄 손잡이로 끌어 바꾼 값이 있으면 그쪽이 이긴다
(`MM_TKEY = 'memo#mm3'`).

- 내용은 **접지 않는다** — 칸을 `white-space:pre-wrap` 으로 두어 줄바꿈째 다 보여 준다.
- **줄을 누르면 그 줄이 그 자리에서 입력칸으로 바뀐다**(`memoEditRow()` — 제목 `<input>`,
  내용 `<textarea>`). 제목 칸을 누르면 제목에, 내용 칸을 누르면 내용에 커서가 간다.
  「완료」·`Esc` 로 읽는 모양으로 돌아오고, 「삭제」는 그 줄에서 바로 지운다.
- 내용 `<textarea>` 는 스크롤을 두지 않고 **글자 수만큼 높이를 늘린다**(`mmGrow()`).
- 입력 중에는 **표를 다시 그리지 않는다** — 그리면 입력칸이 사라져 글자를 이어 쓸 수 없다.
  저장(0.4초 미룸)과 「… 저장됨」 표시만 하고, 줄을 옮기거나 닫을 때 `saveMemoNow()` 로 끝낸다.
- 검색은 그대로 제목 · 본문을 함께 보고, 걸린 글자에 `<mark>` 를 붙인다.
  「+ 새 메모」 · 「텍스트로 내보내기」는 제목 아래 툴바로 옮겼다(예전 왼쪽 목록 위에 있었다).

지운 CSS: `.memo-wrap` · `.memo-list` · `.memo-item`(과 `.snip` · `.wide` · `.code-badge`) ·
`#memo-title` · `#memo-body`. 특정내역이 쓰던 두 칸 배치 규칙도 여기 있었는데 그 화면이
이미 표 한 장이라 함께 지웠다. 새로 넣은 것은 `.mm-title` · `.mm-body` · `.mm-when` ·
`.mm-in` · `.mm-ta` · `.mm-acts` · `.btn.mini` 다.

### 세부작성요령을 원문 모양으로 다시 세우는 법 (2026-08-21)

`data/detail-codes.js` 의 `body` 는 세부작성요령 PDF 를 `pdftotext -table` 로 뽑은 것이라,
♦ 항목 · ※ 주석과 함께 **표가 공백으로 칸을 맞춘 글자 그림**으로 들어 있다.
`js/page-detail.js` 의 `dtDocHtml()` 이 그것을 원문 모양으로 다시 세운다.
**글자는 하나도 바꾸지 않는다** — 줄과 칸만 다시 세우고, PDF 양끝맞춤으로 벌어진 공백만
한 칸으로 줄인다(114건 전부에 대해 "공백 뺀 글자열이 원문과 같은지" 자동 대조로 확인했다).

| 원문 | 화면 |
|---|---|
| `♦` · `◆` 로 시작하는 줄 | 항목 머리줄 (`.dt-dia`) — 작성요령 · 기재형식 · (예시) · 적용일 |
| `<제출자료별 세부코드>` 처럼 `<…>` 만 있는 줄 | 표 이름 (`.dt-cap`) |
| 칸이 맞은 줄 묶음 | `<table class="dt-tb">` — 24건 (MS001 · MT015 · MT018 · CT001 …) |
| `MT018   M002` 처럼 구분코드 + 값 | 기재 예시 상자 (`.dt-ex`) — 108건 |
| 그 밖의 줄 | 글줄 (`.dt-ln`), `※`·`☞` 는 주석 색 |

칸 경계는 **여러 줄이 같은 자리에서 벌어져 있는지**로 찾는다(`dtBoundary`, 3줄 이상 지지).
"모든 줄이 공백인 칸"으로 찾으면 pdftotext 가 한 칸씩 어긋나게 맞춘 표를 못 찾고,
반대로 조건을 낮추면 양끝맞춤으로 벌어진 **글줄이 표로 잡힌다.** 그래서
① 3줄 이상이 같은 컬럼에서 벌어져 있어야 하고,
② 칸이 맞은 줄의 반 이상이 기재 예시 줄이면 표로 세우지 않고 예시 상자로 그리고,
③ 표 앞뒤에 붙은 글줄(`※`·`☞`·`*` 로 시작하는 줄, 표 이름)은 표 밖으로 뺀다.
④ 「적용일」·「기재형식」 항목 안에서는 표를 만들지 않는다 — 날짜가 여러 줄 나란히 서면
   자리가 맞아 표로 잡힌다(MT064 적용일 3줄).
⑤ 벌어진 줄 수가 같은 자리가 여럿이면 **오른쪽 칸 글자가 같은 자리에서 시작하는** 쪽을 고른다
   (칸은 왼쪽정렬로 맞아 있다). 이게 없으면 양끝맞춤으로 벌어진 **문장 속 공백**이 경계로
   잡혀 글자가 옆 칸으로 넘어간다 — 2026-08-21 에 이걸로 네 곳을 고쳤다:
   MT045 `경우`, JS016 `또는 조짐 동반 편두통`, JT010·JT018 머리줄 `사 유`, JT018 `제1편`.

### 칸을 넘어간 줄 (2026-08-21)

원문 칸보다 글자가 길어 옆 칸 자리까지 넘어온 줄은 경계에서 못 쪼갠다. 그런 줄은
`dtSplitLoose` 가 **조각의 가운데가 놓인 칸**으로 넣는다(MT043 `코로나바이러스감염증-19  02`,
JT039 `폐암 외 고형암  04`). 조각이 하나뿐이면 경계 **왼쪽**의 가까운 공백에서 한 번 더 자른다
(MS001 `- 보건기관 등 방문당 진료비 청구시 | 투약일수 미기재`) — 앞 칸 글자가 오른쪽으로
삐져나온 것이므로 자를 자리는 경계 왼쪽이다.

이 느슨한 방식은 **표를 어디서부터 세울지 정할 때는 쓰지 않는다.** 그러면 표 앞 글줄과
표 이름까지 "칸이 맞은 줄"로 보여 표가 위로 번진다(한 번 그렇게 만들어 봤다 — 표 24개가
28개로 늘고 캡션·각주가 표 안으로 들어왔다).

### 쪽이 넘어가며 갈라진 표는 하나로 (2026-08-21)

PDF 쪽이 바뀌면 같은 표가 **머리줄부터 다시** 시작한다. 원문에서는 한 표이므로,
뒤 묶음의 첫 줄이 앞 표의 머리줄과 같으면 **같은 표의 다음 쪽**으로 보고 이어 붙이고
다시 나온 머리줄은 한 번만 그린다. MT015(제출자료별 세부코드) 2쪽 → 표 1개 17행,
MT018(본인부담구분코드) 3쪽 → 표 1개 48행.

**줄만 이어 붙이면 안 된다** — pdftotext 는 쪽마다 칸 위치를 조금씩 다르게 맞춘다.
그래서 표는 쪽묶음(`{lines, bs}`) 목록으로 들고 다니며 **칸 경계를 쪽마다 따로 재고**,
그릴 때만 한 `<table>` 로 합친다(`dtRunParts` → `dtTableHtml(chunks)`).
줄을 먼저 합쳐 경계를 한 번만 재면 두 쪽의 칸이 어긋나 안 쪼개지는 줄이 생긴다.

### 구분 칸 병합(rowspan) 되살리기 (2026-08-21)

원문 표의 구분 칸은 여러 행을 묶는 병합 셀이고, PDF 는 그 글자를 묶음 **가운데**에 놓는다.
그래서 텍스트에는 구분 글자가 묶음 중간의 한두 줄에만 남는다 —
`진료` / `기록부` 두 줄이 실은 6행을 묶는 `진료기록부` 한 칸이다.
`dtSpans()` 가 글자가 있는 줄묶음을 찾고 **묶음 사이 빈 구간의 가운데**를 경계로 봐서
`rowspan` 으로 되살린다(글자는 이어 붙일 뿐 바뀌지 않는다).
MT015 → `진료기록부[6] · 검사결과지[4] · 영상자료[4] · 기타자료[2]` (원문과 같다).

행마다 값이 있는 첫 열(MT018 의 `M001`·`M002` …)은 병합하지 않는다. 가르는 조건은
**첫 칸이 빈 줄이 있어야 하고**, 글자 있는 줄묶음이 전체 행의 절반보다 적고,
각 묶음이 3줄 이내이며 이어 붙인 글자가 12자 이내일 때만 병합으로 본다.
칸을 가로지르는 줄(`tr.wide`)이 섞인 표는 병합하지 않는다 — 묶음 범위가 흔들린다.
묶음이 여러 줄일 때는 **모든 묶음이 같은 줄 수**여야 한다 — 한 줄짜리와 여러 줄짜리가 섞이면
줄마다 다른 값이라는 뜻이다(MT043 의 `전상자`·`기타` 를 `전상자기타` 한 칸으로 묶던 것을 막는다.
MT015 는 네 묶음이 모두 두 줄이라 그대로 병합된다).

**표의 행은 원문 한 줄 = 표 한 줄이다.** 원문에서 한 칸이 여러 줄로 넘어간 것을 묶어
한 행으로 만들지 않는다 — 어디서 행이 끝나는지는 글자만 보고 알 수 없고(PDF 의 칸 선이
텍스트에는 남지 않는다), 잘못 묶으면 심사 기준이 틀어진다. 대신 첫 칸이나 마지막 칸이 빈 줄은
**가로선을 지워**(`tr.cont`) 위 줄과 한 칸처럼 읽히게 한다. 남는 한계는 두 가지다.

- 이어지는 줄인데 양쪽 칸이 다 채워져 있으면(MS001 의 `(의약분업예외구분코드 "45")` 줄)
  가로선이 한 줄 더 그려진다. 글자는 제자리다.
- 칸 사이가 공백 한 칸으로 붙어버린 줄은 나눌 수 없어 한 칸을 통째로 쓴다(`tr.wide`, 6줄).

### 마지막 칸의 줄바꿈은 이어 붙인다 (2026-08-21)

원문 표는 좁은 칸 폭에 맞춰 글자를 끊어 넣는다. 화면의 칸은 그보다 넓어 그 끊김이
뜻 없는 줄바꿈으로 보인다(MT018 M013 의 `노숙인 1종`). **마지막 칸만 채워진 줄**은
앞이나 뒤 행의 마지막 칸에 이어 붙인다(`dtJoinFrags`). MT018 은 47행 → **35행**,
구분코드 한 개가 한 행이 된다.

어느 행에 붙는지 — PDF 는 구분코드를 칸 **가운데** 줄에 놓아서 조각이 코드 줄 아래에
오기도(M013) 위에 오기도(B007) 한다. 아래 순서로 가른다.

1. `- ` · `·` · `1.` 로 시작하면 같은 칸의 **새 줄머리**다 → 앞 행에 `<br>` 로 붙인다(MS001).
2. 괄호·마침표·조사(에서·을·의 …)로 시작하면 앞 글자에 딱 붙는다 → 앞 행, 공백 없이.
3. 앞 행의 마지막 칸이 `)` 로 끝나고(문장이 닫혔다) 뒤 행이 새 코드로 시작하면 → **뒤 행**.
4. 그 밖에는 앞 행.

**띄어쓰기가 문제다.** 원문은 칸 끝에서 글자를 끊을 때 공백을 남기지 않아, PDF 글자만으로는
그 자리에 공백이 있었는지 알 수 없다(`-raw`·`-table`·`-lineprinter` 를 다 확인했다).
그래서 **붙여 쓸 근거가 있을 때만** 붙이고 그 밖에는 띄운다(`dtNoGap`).

- 닫는 괄호·마침표·조사로 시작하거나, 여는 괄호가 열린 직후에 끊겼으면 붙인다.
- 그 밖에는 붙여 쓴 꼴이 **세부작성요령 다른 줄에 실제로 있는지** 본다(앞말 끝·뒷말 머리
  네 글자씩, 판가름이 안 나면 두 글자씩, 두 꼴이 다 있으면 더 자주 쓰인 쪽).
  `선택의료급`+`여기관이` → `선택의료급여기관` 이 원문에 흔해 붙이고,
  `이용하는`+`노숙인` → `이용하는 노숙인` 이 원문에 있어 띄운다.
- 대조는 줄 단위로 한다 — 지금 합치려는 그 자리가 근거로 잡히면 안 된다.

MT018 의 이어 붙인 자리 12곳을 원문과 한 줄씩 대조해 확인했다. 아직 이어 붙이지 않는 것:
**여러 칸이 동시에 이어지는 줄**(MS001 의 구분 칸, MT020·MT040 의 기재대상 칸)은 그대로
가로선 없는 줄로 둔다 — 그 칸들은 원문에서 행을 넘어 병합돼 있어 어디까지가 한 칸인지
글자만으로 가를 수 없다.

### 자동으로 못 가르는 표는 손으로 적어 둔다 — `DT_FIX` (2026-08-21)

행 경계를 글자만으로 가를 수 없는 표가 있다. 구분코드가 칸 **가운데** 줄에 놓여 있어
그 위아래 줄이 어느 칸에 딸린 것인지 모르고, 자동 규칙이 틀리면 **심사 기준이 어긋난다.**

- MT064 — `다태아 분만 중` 이 E 칸인데 C 칸에 붙었다.
- MT065 — 넉 줄·여섯 줄짜리 칸이 줄마다 잘려 코드 A·B·C·D 가 문장 중간에 떠 있었다.

이 두 표는 `js/page-detail.js` 의 **`DT_FIX`** 에 원문 PDF 를 보고 확인한 행 경계를 적어 뒀다.
`rows` 가 행마다 원문 줄 번호, `sub` 는 그 행 안에서 값이 여러 개인 열을 다시 나누는 묶음
(MT064 의 C 행은 유형상세가 코로나…/특별재난 둘이라 두 줄로 나뉜다).
글자는 여기 적지 않는다 — 데이터에서 읽어 이어 붙이므로 옮겨 적다 틀릴 일이 없다.

**고시가 개정되면 자동으로 무시된다.** `probe`(그 줄이 이 글자로 시작해야 한다)와 줄 수(`n`)가
안 맞으면 손으로 적은 값을 버리고 원래(자동) 방식으로 그린다. 개정 후에는 이 두 표를 다시 보고
`DT_FIX` 를 고치면 된다. 표가 또 잘못 묶이면 같은 방식으로 한 줄 추가하는 것이 정답이다.

표 뒤 각주 판정도 함께 고쳤다 — 맨 끝의 칸이 안 맞는 줄 묶음에서 `*`·`※`·`☞` 로 시작하는
**첫 줄부터** 각주로 본다. 예전에는 그 묶음을 통째로 밀어내 MT065 의 마지막 표 줄
(`수가 적용하는 명세서를 …`)이 표 밖으로 빠져 있었다.

### 전체 훑기 — 무엇을 확인했나 (2026-08-21)

표 24개를 한 번에 훑어 **글자가 다른 칸으로 넘어간 곳**을 찾는 검사를 만들어 돌렸다.
① 코드 칸(값이 대개 4자 이내인 마지막 열)에 문장이 든 행, ② 한 글자만 든 칸(머리줄이 잘린 흔적),
③ 칸 하나만 채워진 행(아직 안 붙은 조각), ④ 통째로 한 칸을 쓴 행(`tr.wide`) — **모두 0건**이다.
글자 대조(공백 뺀 글자열)도 그대로다. 새 판을 넣은 뒤에는 같은 검사를 다시 돌려 보면 된다.

### 칸 속에 칸이 있는 표는 칸을 손으로 짚는다 — `DT_FIX` 의 `grid` (2026-08-21)

MT043(유형상세 안에 `이태원사고` + `공단대납` 두 칸)과 JT039(조직유형 앞에
`진행성·전이성·재발성 폐암` 묶음 칸)는 **머리줄이 4개·2개인데 값 자리가 5개·3개**다.
칸 경계로는 세울 수 없어(한 칸에 값 둘이 들어간다) 칸 하나하나를 손으로 짚어 뒀다.

```js
'MT043|0': { grid:true, pieces:[4,5,3,4,4,2], probe:[[1,0,'특별재난'], …],
  head:[{p:[[0,0]]}, {p:[[0,1]]}, {p:[[0,2]], cs:2}, {p:[[0,3]]}],
  rows:[[{p:[[1,0]], rs:2}, {p:[[1,1]], rs:2}, {p:[[1,2],[2,0]], rs:2}, …], …] }
```

- `p:[[줄, 조각], …]` — **원문의 그 조각을 가리킨다.** 글자를 옮겨 적지 않으므로 틀릴 일이 없고,
  조각이 여럿이면 `dtNoGap` 규칙으로 이어 붙인다(`이태원`+`사고` → `이태원사고` — 통합본
  작성요령도 붙여 쓴다). 줄 번호는 **머리줄을 0** 으로 세고, 조각은 공백 두 칸으로 끊은 순서다.
- `rs`·`cs` — 세로·가로 병합. 원문 그대로 `유형상세` 머리줄이 두 칸을 덮고(`cs:2`),
  `이태원사고` 는 두 행을 덮는다(`rs:2`).
- `pieces`(줄마다 조각 개수)와 `probe`(그 조각이 이 글자로 시작해야 한다)가 안 맞으면
  **손 댄 값을 버리고** 자동 방식으로 그린다 — 고시가 개정되면 자동으로 안전한 쪽으로 돌아간다.

조각 나누기(`dtPieces`)는 **공백 두 칸 이상**에서 끊고 낱말 사이 한 칸은 조각 안에 둔다.
예전 정규식은 `1        이태원` 을 한 조각으로 잡아(선택 그룹이 탐욕적) 한 칸에 값 둘이
들어갔다 — 2026-08-21 에 `/\S+(?: \S+)*/` 로 바로잡았다.

### 나열 순서 (2026-08-21)

구분코드의 앞 두 글자를 **MS → MT → MX → JS → JT → JX → CT** 순으로 세우고, 그 밖의 것
(JB · JJ · MB · MJ)은 뒤에 오름차순으로 붙인다(`DT_PREFIX`·`dtOrder`). 같은 묶음 안에서는
코드 오름차순, 같은 코드면 적용일자 순이라 지난 판이 뒤에 온다.
검색해도 이 순서는 흔들지 않는다 — 다만 `MT002` 처럼 **코드를 그대로 친 경우**에만
그 코드를 맨 위로 올린다(다른 코드의 작성요령이 그 코드를 언급만 해도 검색에는 걸리기 때문).
- 첫 칸 자리보다 **왼쪽에서 시작하는 줄**도 한 칸으로 통째로 쓴다. 어느 칸에 딸린 글자인지
  글자만 보고 알 수 없기 때문이다(앞 줄에 붙는 경우도, 뒤 줄에 붙는 경우도 있다).
  2026-08-21 에 데이터의 들여쓰기를 바로잡아 이 경우는 거의 없어졌다(위 데이터 절 참조).
- 표 뒤 각주는 맨 끝에서 칸이 안 맞는 줄들을 묶어 보고 그 안에 `*`·`※`·`☞` 줄이 있으면
  표 밖으로 뺀다(각주 둘째 줄부터는 글머리표가 없다 — MT065).

## 의료급여 외래의 MT018 표는 심평원 안내표가 아니다

의료급여 · 외래진료시 맨 아래 「특정내역 MT018 — 본인부담구분코드」 카드는
**심평원 본인부담기준 안내표에 없는 표**다. 출처가 다르다 —
「요양급여비용 심사청구서·명세서 세부작성요령」 Ⅸ. 특정내역 구분코드 **219쪽** MT018 작성요령의
`<본인부담구분코드>` 표이고, 실제로는 `data/detail-codes.js` 의 MT018 `body` 에 이미 들어 있던 글을
표로 옮긴 것이다. 실무에서 외래 본인부담을 볼 때 같이 찾는 값이라 이 화면에 뒀다.

- **34행** — M001~M005 · M007~M019 · B001~B015 · B030.
  **M006 은 원문에 없다**(빠진 것이 아니라 원문이 그렇다). 추측해 채우지 않았다.
- 원문 표가 쪽을 넘기며 줄바꿈된 것을 한 행으로 이어 붙였다. 글자는 고치지 않았다.
  이어 붙일 때 **낱말 중간에서 끊긴 곳은 공백 없이** 붙였다 — B007 의 `선택의료급` + `여기관이`,
  B008 의 `(치과의원)` + `에서`, B013·B014 의 `(2종)`·`(1·2종)` 이 그렇다.
  나머지는 어절 경계라 공백으로 이어 붙였다.
- 세부작성요령이 개정되면 `data/detail-codes.js` 를 다시 만든 뒤 이 표도 같이 고쳐야 한다.
  같은 내용이 두 곳에 있는 셈이라, 특정내역 화면의 MT018 과 값이 어긋나지 않게 본다.

병합 셀(rowspan·colspan)은 값을 반복해 격자로 풀어 둔다. 화면에서는 첫 열이 이어지는 만큼

표 칸 안에 문단만큼 긴 설명이 든 경우(건보 외래 상급종합의 "의약분업 예외환자" 범위)만
칸에는 항목명을 남기고 설명을 notes 로 내린다.

검색은 그 제도의 **모든 탭**을 훑고, 주석(notes)에만 걸려도 그 표를 보여 준다 —
특정 항목 부담률(추나·격리·선별급여 등)이 대부분 표가 아니라 주석에 적혀 있기 때문이다.

심평원 표는 본표 아래에 "주) 본인부담률을 달리 운영하고 있는 특정 항목 및 본인부담률" 목록을
따로 두는데, 건강보험 외래는 이 목록을 같은 표 안에 이어 넣고 `rows` 중간에 `[B2_SUB]` 한 줄을
끼워 띠로 구분한다(`table.b2 td.subh`). 값이 정확히 `B2_SUB` 인 행만 띠가 되므로, 의료급여 외래의
"* 그 밖의 외래진료"처럼 진짜 한 열짜리 표는 영향을 받지 않는다. 검색 중에는 행이 띄엄띄엄해져
띠가 무엇을 이끄는지 알 수 없으므로 띠를 빼고 그린다. 건강보험 입원·의료급여 외래는 원문이
아예 별도 표로 두고 있어 지금처럼 카드를 나눠 둔다.

한 카드 안에 표가 여럿 필요한 경우(건강보험 외래 의원급)는 섹션에 `head`/`rows` 대신
`subs:[{sub, head, rows}, …]` 를 둔다. `sub` 는 표 위에 얹는 소제목 띠(`.b2-subh`)다.
의원급은 원문이 "65세 이상 1·2 / 65세 미만" 세 표로 나뉘어 있지만 열 구성이 서로 달라
한 표로 합칠 수 없어, 카드 하나 안에 표 넷(65세 이상 ×2 · 65세 미만 · 합친 주) 목록)으로 둔다.
`codes`(특정기호)와 `notes`(각주)는 섹션 단위라 모든 sub 에 함께 걸린다.

차상위1종(C)도 2026-08-20 에 같은 방식으로 묶었다. 원문이 "전종별 0원" 한 줄과 그 아래
"주) 특정 항목 본인부담률" 목록을 한 덩어리로 두고 있어, 카드 둘로 떨어져 있던 것을
카드 하나 안의 표 둘(`입원·외래` · `주) 특정 항목 본인부담률`)로 합쳤다.
제목 뒤에 있던 "— 입원·외래" 는 첫 표의 소제목 띠로 옮겼다(글자는 그대로).
띠는 `.b2-card .b2-scroll + .b2-subh` 로 위쪽 선을 받는다 — 표가 `.b2-scroll`
(`display:contents`) 안에 있어 `table.b2 + .b2-subh` 로는 선택자가 걸리지 않는다.

차상위2종 입원도 같은 날 같은 방식으로 묶었다(본표 + `주) 특정 항목 본인부담률`). 원문에
본표의 제목이 없고 카드 제목이 이미 "입원"이라 본표에는 띠를 얹지 않고 `주)` 띠만 둔다 —
`subs` 의 첫 항목에 `sub` 를 안 쓰면 그렇게 그려진다. 섹션의 `notes`(※ 종별 변경)는
카드 하나 아래로 한 번만 붙는다.

차상위 카드 제목은 2026-08-20 에 사용자 요청으로 짧게 줄였다 — 원문 표 제목
"(차상위1종, 공상등구분 C) 차상위 희귀질환 및 중증난치질환 또는 중증질환 본인부담경감대상자" →
`차상위 1종: C`, "(차상위2종 E / 차상위2종 장애인 F) 입원/외래" → `차상위 2종: E,F — 입원/외래`.
남긴 `C` · `E,F` 는 공상등구분이다. 대상(희귀·중증난치질환 등) 설명은 제목에서 빠졌다.
`— 입원`/`— 외래` 를 뒤에 붙여 둔 것은 두 카드를 아이콘으로만 가리게 두지 않으려는 것이고,
`B2_ICON` 이 제목으로 입원·외래를 갈라 아이콘을 고르기 때문이기도 하다.

같은 날 **건보 기타의 `등록 틀니`·`등록 치과임플란트` 표 안의 구분 값**도 같은 방식으로 줄였다.
이쪽은 카드 제목이 아니라 **행 값**이라 `data/burden-hira.js` 를 고쳤다(6칸).

| 원문 | 바꾼 값 |
|---|---|
| (차상위1종, 공상등구분 C) 차상위 희귀질환 및 중증난치질환 또는 중증질환 본인부담경감 대상자 | `차상위 1종: C` |
| (차상위2종, 공상등구분 E) 차상위 만성질환 · 18세미만 본인부담경감대상자 | `차상위 2종: E` |
| (차상위2종 장애인, 공상등구분 F) 차상위 장애인 만성질환 · 18세미만 본인부담경감대상자 | `차상위 2종: F` |

남긴 `C`·`E`·`F` 는 공상등구분이다. **대상 설명**(희귀·중증난치질환 / 만성질환·18세미만 /
장애인 만성질환·18세미만)은 화면에서 빠졌으니, 그 구분이 필요하면 되살려야 한다.
E 와 F 는 부담률이 같아(15% · 20%) 값 칸이 하나로 병합돼 보이는데, 이름을 줄이기 전에도 그랬다.

카드 제목 앞 아이콘은 `js/page-burden.js` 의 `B2_ICON` 에 있다. 1종은 입원·외래가
한 표라 종으로(1️⃣), 2종은 표가 갈려 있어 진료형태로(🛏️ 입원 · 🚶 외래) 구분한다.

표 하나에만 걸어야 하는 클래스는 `B2_TCLS`(제목 → 클래스)에 모아 둔다. 건보 입원표의
`roomy`(여백 확대)가 여기로 들어왔고, 차상위 2종 입원표의 `gubun65` 가 더해졌다.

건보 외래의 "외래 공통 (연령·유형별)" 묶음은 2026-08-19 에 종별 표 안으로 옮겼다. 원문은
"일반환자 본인부담률의 70%" 처럼 비율로만 적혀 있어 종별 일반율에 70% 를 곱한 값(상종 42% ·
종합 35% · 병원 28% · 의원 21%)을 적어 둔다. 조산아·저체중출생아 5%, 난임진료 30% 은 종별이
같아 그대로 넣었고, 원문이 "보건기관 정액, 약국·한국희귀의약품센터의 직접조제는 제외"라고
적고 있어 65세 이상 표와 약국 표에는 넣지 않았다. "건강검진 확진 의료비 지원",
"상급종합병원 경증질환 외래진료" 두 줄은 사용자 요청으로 뺐다.

옛 ① 화면(사내 엑셀 `data/burden-rules.js`)은 2026-08-19 에 삭제했다. 데이터 파일과
`tools/burden.awk` 는 지우지 않고 남겨 뒀지만 어디서도 읽지 않는다 — 되살리려면
`index.html` 에 `<script src="data/burden-rules.js">` 를 다시 걸고 화면 파일을 새로 만들어야 한다.

## 심평원 원문의 병합 셀 되살리기

심평원 표는 같은 값이 이어지는 칸을 세로·가로로 병합해 둔다. 데이터(`data/burden-hira.js`)는
격자로 풀어 저장하므로, 화면에서 다시 묶는다. **값이 같으면 원문도 병합돼 있다**는 것을 근거로 쓴다.
두 제도 모든 탭(31개 표)에 같은 규칙이 걸린다 — 표마다 따로 정하지 않는다.

계산은 모두 **화면에 그릴 값**(`vis` = 감춘 열을 뺀 배열)으로 한다. `근거`·`끝수계산` 을 감추면
열 번호가 밀리므로, 원본 배열과 화면 배열을 섞어 쓰면 자리가 어긋난다.

### 세로 병합 (rowSpan)

| 열 | 규칙 | 함수 |
|---|---|---|
| 첫 열 | 값이 이어지는 만큼 | `b2SpansCol(vis, 0)` |
| `구분` · `대상` | 0번째부터 그 열까지 **모두** 같아야 (앞 열에 딸린 이름 칸) | `b2SpansHier` |
| 그 밖의 모든 열 | 값이 같고 **첫 열도 같을 때**. 빈 칸도 묶는다 | `b2SpansIn(…, 0, true)` |

`구분`·`대상` 을 더 엄격하게 보는 이유는 종별이 바뀌었는데 이름 칸이 이어져 보이면 안 되기 때문이다.
나머지 열을 **첫 열 묶음 안으로 제한**하는 것이 과잉 병합을 막는 장치다 —
첫 열이 항목처럼 행마다 다른 표(차상위 1종의 주) 목록)에서는 묶을 그룹이 없어 아무것도 묶이지 않는다.
실제로 그 표의 `원격협의진찰료 자문료` · `상급종합병원 회송료` 는 둘 다 `해당 비용의 0%` 인데
핸드오프 레퍼런스처럼 **따로** 그려진다.
빈 칸을 묶는 것은 원문이 빈 칸도 하나로 병합해 두기 때문이다(건보 기타 첫 표의 비고 ① 5행).

### 가로 병합 (colSpan)

원문에서 왼쪽 칸과 하나로 병합된 열이다. **"세부 바로 왼쪽 열이 흡수한다"** 로 두면
표마다 흡수하는 열을 정할 필요가 없다 — 차상위 외래에서는 `구분`, 건보 기타에서는 `대상` 이다.

| 열 | 흡수 조건 |
|---|---|
| `세부` | 값이 비었을 때 |
| `6세미만` | 값이 **왼쪽 칸과 같을 때** (원문도 두 칸을 합쳐 한 값만 적는다) |

가로 병합은 이 두 열에만 준다. `1종 수급권자`·`2종 수급권자` 처럼 값이 같아도 원문이
따로 두는 열이 있어 "값이 같으면 가로로 합친다"를 모든 열에 적용하면 안 된다.

흡수된 행에는 그 칸이 아예 없으므로 **세로 묶음 계산에서 떼어 놓는다**(그 행 값을 유일한 값으로
바꿔 이어지지 않게 한다). 그러지 않으면 없는 칸을 묶으려 해서 격자가 어긋난다.

### 검증

두 제도 모든 탭을 훑어 표마다 **격자 무결성**(겹침·구멍·넘침 0)을 확인한다.
행마다 `rowspan`·`colspan` 을 펼쳐 격자를 채워 보는 방식이라, 병합이 하나라도 어긋나면 바로 잡힌다.
검색 중에도 행을 지우지 않고 흐리게만 하므로 병합이 그대로 유지된다.

## 열 너비 손으로 조절 — 모든 화면 (2026-08-20)

머리줄 칸 사이 경계에 커서를 대면 `col-resize` 로 바뀌고(파란 선이 뜬다) 끌어서 너비를 바꾼다.
**모든 화면의 표에 걸린다.** 기능은 `js/common.js` 에 있다 — 두 개 이상의 화면이 쓰므로.

- **두 열이 폭을 주고받는다.** 왼쪽 열이 넓어지는 만큼 바로 오른쪽 열이 좁아져 **표 전체 폭은 변하지 않는다.**
  좌우 스크롤을 만들지 않는다는 전제를 지키려는 것이다 — 한 열만 넓히면 표가 카드를 넘겨 가로 스크롤이 생긴다.
- 끌기 시작할 때 `pinWidths()` 가 지금 보이는 너비를 그대로 못박고 표를 `fixed` 로 바꾼다.
  auto 표도 이때 fixed 가 된다. 그러지 않으면 한 열만 건드려도 브라우저가 나머지 열을 다시 계산한다.
- 두 열 모두 최소 `COLW_MIN`(48px)은 남긴다. 마지막 열에는 손잡이가 없다 — 잡을 오른쪽 짝이 없다.
- **손잡이를 두 번 누르면** 그 표가 처음 너비로 돌아간다.

### 행이 많은 표는 안내선으로 끈다 (2026-08-21 — 렉 잡기)

행이 많은 표에서 열 너비를 끌면 **화면이 멎은 것처럼 느려졌다.** 원인은 이렇다.

열 폭을 1px 바꾸면 `table-layout:fixed` 라도 그 두 열의 글자를 **모든 행에서 다시 흘려야** 해서
표 전체가 다시 배치된다. 한 번에 걸리는 시간을 재 보니

| 표 | 행 | 한 번 배치 |
|---|---|---|
| ① 본인부담금 규칙 카드 | 8 | 0.7ms |
| 특정내역 | 164 | 13ms |
| [별표12] 소아가산 | 618 | **32ms** |
| 응급의료행위 | 1,277 | **54ms** |

마우스는 1초에 100번 넘게 움직이는데 한 번에 32~54ms 가 걸리니 따라올 수가 없었다.

**고친 방법 — 엑셀처럼 세로 안내선(`.rz-line`)만 옮기고, 폭은 놓을 때 딱 한 번 준다.**
끄는 동안 표는 건드리지 않으므로 행 수와 상관없이 비용이 일정하다.
행이 `RZ_LIVE_ROWS`(60)보다 많은 표에만 적용하고, 작은 표는 원래대로 바로 따라 움직인다
(0.7ms 라 공짜이고 그 편이 보기 좋다). 잰 값:

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 마우스 한 번 움직일 때 (618행) | 32ms | **0.007ms** |
| 마우스 한 번 움직일 때 (1,277행) | 54ms | **0.003ms** |
| 놓을 때 | 100ms | **0.5ms** |

같이 손본 것 두 가지.

- **안내선은 `requestAnimationFrame` 을 쓰지 않는다.** 위치만 바꾸면 되니 바로 옮긴다 —
  rAF 는 화면이 가려지면 멈춰서 선이 그 자리에 굳는다. 표를 따라 움직이는 쪽(작은 표)만
  프레임당 한 번으로 모은다.
- **놓을 때 너비를 다시 재지 않는다.** 예전에는 폭을 준 직후 `getBoundingClientRect()` 로
  일곱 칸을 다시 읽어 배치가 한 번 더 돌았다(놓는 순간 100ms). 지금은 `pinWidths()` 가
  누를 때 잰 값에서 바뀐 두 칸만 계산해 넣는다.

안내선은 마우스를 누른 자리가 아니라 **그때의 열 경계**(`th.getBoundingClientRect().right`)에서
시작한다 — 손잡이가 9px 폭이라 누른 자리는 경계에서 몇 px 어긋나 있다.

### 손잡이를 다시 꽂는 방법

화면을 다시 그리면(검색 · 필터 · 탭 이동) 손잡이가 사라진다. **각 화면의 렌더 함수를 고치지 않고**
`watchTables()` 가 `#main` 을 `MutationObserver` 로 지켜보다가 바뀔 때마다 `addGrips()` 로 다시 꽂는다
(40ms 디바운스). 새 카테고리를 추가해도 표에 `<thead>` 만 있으면 자동으로 따라온다.

### 표 안의 표도 조절된다 (2026-08-21)

특정내역의 **세부작성요령 안에 있는 표**(`table.dt-tb`, 28개)에도 손잡이가 붙는다. 두 가지를 고쳤다.

- `addGrips` 가 보는 표에 `table.dt-tb:not(.dt-ex)` 를 넣었다. 기재 예시 상자(`.dt-ex`)는 두 칸짜리
  작은 상자라 제외한다 — 끌면 폭이 100% 로 늘어나 모양이 바뀐다.
- 머리줄(`<thead>`)이 없는 표도 있을 수 있어, 너비를 재는 줄을 `headCells()` 하나로 모았다
  (thead 첫 줄 → 없으면 tbody 첫 줄, 칸이 하나뿐이면 조절 안 함). `colwKey`·`pinWidths`·
  끌기·두 번 누르기가 모두 이 함수를 쓴다.

본문 표의 이름(`data-k`)은 **`dtb|코드|적용일자|그 코드 안에서 몇 번째 표`** 다(`page-detail.js`).
화면 순서로 세면 검색·필터로 행이 걸러질 때마다 어긋나기 때문이다.
본문 표는 칸 폭이 카드 안에서만 오가므로 조절해도 페이지 가로 스크롤은 생기지 않는다.

### 표 끝선(맨 오른쪽 세로줄)도 옮긴다 — 본문 표만 (2026-08-21)

본문 표는 마지막 열에도 손잡이(`.rz-end`)가 붙는다. 그 자리는 짝이 될 오른쪽 열이 없으니
**마지막 열과 표 전체 폭을 같이** 늘리고 줄인다(`endMode`). 칸(부모)보다 넓어지지 않게 자른다 —
표가 칸을 넘으면 페이지에 가로 스크롤이 생기기 때문이다. 값은 열 너비와 같은 저장소에
`이름|w` 로 넣고(`colwEndOf`), 손잡이를 두 번 누르면 열 너비와 함께 지워진다.

카테고리 화면의 큰 표(`table.b2`·`table.fields`)에는 끝선 손잡이를 두지 않는다 —
카드 폭을 꽉 채우는 것이 규칙이다(`RZ_END_SEL` 로 가른다).

표이름은 표가 스스로 `data-k` 를 달아 두면 그것을(① 카드들은 `제목#표번호` — 검색으로 카드가
걸러져 순서가 바뀌어도 같은 표를 가리킨다), 없으면 `화면id#표순서#열수` 로 만든다.
저장값은 **열 개수가 지금과 같을 때만** 쓴다 — 열을 감추거나 늘리면 자리가 어긋나기 때문이다.
①에서는 `B2_COLW`(핸드오프 지정 너비)보다 이 값이 우선이다.
**손잡이를 두 번 누르면** 덧쓰기만 지우고 소스 기본값으로 돌아간다.
소스 기본값도 없는 표는 각 `page-*.js` 의 % 기본값(`BT_ACT_COLW` 등)으로 돌아간다.
이 브라우저의 덧쓰기를 전부 지우려면 `localStorage.removeItem('samguide_colw')`.

### 「열 너비 기본값으로 굳히기」 — 사이드바 맨 아래 (2026-08-21)

너비를 맞춰 놓고 이 버튼을 누르면 **지금 너비가 `data/colw-defaults.js` 에 써진다.**
깃에 올려 두면 브라우저 데이터를 지우든 다른 PC 에서 열든 같은 너비로 열린다.
누르고 나면 이 브라우저의 덧쓰기는 지운다 — 안 지우면 덧쓰기가 계속 기본값을 가려서
"굳혔는데 다른 PC 에서만 안 맞는" 상태를 못 알아챈다.

- `serve.ps1` 로 열었으면(<http://localhost:8392>) 파일을 **바로 덮어쓴다.**
  `serve.ps1` 이 `PUT /data/colw-defaults.js` 하나만 받아 그 파일에 쓴다 —
  경로를 안 가리면 localhost 서버가 프로젝트 어디든 덮어쓸 수 있어서 **이 한 경로만** 허용하고
  나머지 PUT 은 403 으로 막았다(256KB 상한).
- `index.html` 을 더블클릭해 연 경우(`file://`)는 PUT 이 안 되므로 **파일을 내려받는다.**
  받은 `colw-defaults.js` 를 `data/` 에 덮어 넣으면 같은 결과다.

파일을 새로 쓴 뒤에는 **깃에 올려야** 다른 PC 에 넘어간다 — 커밋 대상은 `data/colw-defaults.js` 하나다.

### 열 너비가 아닌 폭도 같이 굳히려면 — `COLW_EXTRA` (2026-08-24)

질병군 계산기의 **「칸 폭」·「표 폭」 슬라이더**는 열 너비와 저장소가 다르다(`samguide_drg`).
그래서 굳히기가 그냥은 담지 못했다 — 슬라이더를 줄이고 눌러도 파일 내용이 그대로였다.

폭을 하나 더 굳히고 싶은 화면은 `COLW_EXTRA` 에 **읽어 오는 함수**를 등록한다.

```js
// js/page-drg.js
COLW_EXTRA['drg|paneW']  = () => dg.width;
COLW_EXTRA['drg|tableW'] = () => dg.tableW;
```

굳히기가 이 값을 읽어 같은 파일에 **숫자 하나**로 넣는다(`"drg|paneW": 800`).
받는 쪽은 처음 값을 정할 때 파일을 먼저 본다 — `dgDefW()` 가 그 일을 하고,
슬라이더 범위 밖의 값은 무시한다.

열 너비는 배열, 이런 낱개 폭과 표 끝선(`|w`)은 숫자다 — 굳히기가 "N개 표" 를 셀 때
**배열인 것만** 센다.

#### 받는 쪽은 "직접 바꿨다" 표시가 있어야 저장분을 따른다 (2026-08-24 — 모든 PC 에서 980 이던 버그)

굳혀 둔 800px 이 **어느 PC 에서도 안 먹고 980 으로만 보이던** 문제가 있었다. 원인은 이렇다.

`dgRefresh()` 는 끝에서 `dgSave()` 를 부르고, 그 `dgRefresh()` 가 화면을 열 때 한 번 돈다.
즉 **질병군 계산기를 한 번 열기만 해도** 그때의 폭(980)이 `samguide_drg` 에 박힌다.
예전 `dgLoad()` 는 저장분에 폭이 있으면 무조건 따랐으므로, 사이트를 한 번이라도 연 PC 는
그 뒤로 파일 기본값이 영영 먹히지 않았다. "새 브라우저에서만 먹는" 기능이었던 셈이다.

그래서 **`wSet` 표시**를 뒀다.

- `wSet:true` 는 **슬라이더를 직접 움직였을 때만** 붙는다.
- `dgLoad()` 는 `wSet === true` 일 때만 저장된 폭을 따르고, 아니면 굳혀 둔 기본값으로 간다.
- 표시가 없는 **옛 저장분은 저절로 풀린다** — 따로 지우라고 안내할 필요가 없다.
- 「비우기」는 `wSet` 까지 그대로 둔다(폭·메모는 계산을 지워도 남긴다).
- 굳히기가 성공하면 `COLW_EXTRA_DONE` 이 `wSet` 을 내린다 — 방금 파일에 넣은 값이 곧 기본값이라,
  표시를 남겨 두면 그 값이 자기 자신을 가린다.

**같은 함정이 다른 화면에도 있다.** 저장분을 자동으로 쓰는 화면(`...Save()` 를 렌더 끝에서
부르는 곳)에 굳히기용 값을 새로 붙일 때는, "사용자가 직접 바꿨다" 와 "그냥 딸려 저장됐다" 를
반드시 구분해야 한다.

### 저장은 px, 화면에 넣을 때는 비율(%) — 가로 스크롤을 막는 핵심

`table-layout:fixed` 는 열 너비의 합이 표 폭보다 크면 **표를 그만큼 넓힌다.** `width:100%` 는
최소값일 뿐이다. 그래서 저장해 둔 px 을 그대로 넣으면 **넓은 모니터에서 굳힌 값을 좁은 창에서
열 때 표가 창을 넘어 페이지에 가로 스크롤이 생긴다**(실제로 1265px 창에서 606px 생겼다).

그래서 저장은 잰 값(px) 그대로 두고, **화면에 넣을 때만 합을 100%로 보고 비율로 환산**한다
(`colwCss()`). 어느 창 너비에서도 사용자가 정한 비율 그대로 꽉 맞게 들어간다.
표 끝선(`|w`)도 칸(부모) 폭을 넘지 않게 자른다.

`page-*.js` 가 `<th>` 에 너비를 직접 박는 화면(①·특정내역·메모장·소아가산…)은
`colwOf(...).map(n => n + 'px')` 가 아니라 **`colwCss(key, 열수)`** 를 써야 한다.
`applyColW()` 가 뒤따라 % 로 덮어쓰기는 하지만, 그 사이 한 프레임 동안 넓은 표가 비친다.

## 상단 바 고정 · 표 형식 통일 (2026-08-20)

### 불변 규칙을 어떻게 지켰는지

1. **테마·글씨 크기** — 본문 13px / 열 머리 12px / 카드 제목 14px / 페이지 제목 20px.
2. **모든 요율·금액은 파랑 볼드** — 기존 `boldNums()` 가 `<b>` 로 감싸고 `table.b2 td b` 가
   `--accent`/700 이다(핸드오프 `.cp-val` 과 같다). 그 외에는 볼드를 쓰지 않는다.
3. **`table-layout:fixed` + `<th>` 인라인 `width`** — `colgroup/col` 은 쓰지 않는다.
   너비는 `B2_COLW`(`제목#표번호` → 배열)에 모아 두고 `fixed` 클래스와 함께 건다.
   **너비를 정하지 않은 표에는 fixed 를 걸지 않는다** — 걸면 열이 균등분배되어 원래 문제로 돌아간다.
   그 표들은 `width:max-content` 로 남는다.
4. **감싸개에 `overflow` 금지** — `overflow` 가 걸린 조상이 sticky containing block 이 되어
   머리줄 고정이 깨진다. 카드에 `overflow:hidden` 을 쓰지 않는다(특정기호 툴팁도 같은 이유로 잘린다).
   둥근 마감은 카드 `border-radius:10px` + 마지막 줄 아래선 제거(`.nb`)로 낸다.
5. **`word-break:keep-all`** — 어절이 한 글자씩 쪼개지지 않게. 다만 `V191,V192,V268…` 처럼
   공백 없는 긴 코드는 칸을 넘치므로 `overflow-wrap:anywhere` 를 같이 준다
   ("달리 넣을 수 없을 때만" 끊으므로 keep-all 을 해치지 않는다).
6. **검색은 행을 숨기지 않고 흐리게(dim)** — `tr.is-dim{opacity:.3}`.
   **이게 실제 버그를 고쳤다.** 전에는 검색 중 행을 걸러내면서 rowSpan 묶음이 무너지므로
   병합을 아예 껐다. 이제 행이 그대로 남아 검색 중에도 병합이 유지된다.
   일치 건수는 검색칸 왼쪽에 `N건 일치`(12px/600 액센트).
   제도 전체를 훑어 걸린 카드만 보여 주는 동작은 그대로다 — 안 걸린 카드까지 다 띄우면 검색이 무의미해진다.
7. **셀 텍스트 무수정** — 원문 그대로다. 핸드오프 레퍼런스가 상급종합병원의 장애인 칸을 `—` 로
   비워 두었지만 **따르지 않았다.** 실제 원문은 그 행에도 문구가 들어 있다(아래 참조).

핸드오프의 외래 표는 장애인 칸 rowspan 이 **5 / 9 / 6** 으로 요양종별 묶음과 같다.
문구가 같아도 종별이 바뀌면 끊어야 한다는 뜻이고, 이것이 위 「심평원 원문의 병합 셀 되살리기」의
"첫 열 묶음 안에서만" 규칙이 나온 계기다. 전에는 상급종합병원과 종합병원군의 문구가 같아
14행이 통째로 묶여 있었다.

레퍼런스는 상급종합병원의 장애인 칸을 `—` 로 비웠지만 **원문에는 종합병원군과 같은 문구가 있다.**
불변규칙 7(셀 텍스트 무수정)이 우선이라 원문을 남겼다. 비우려면 `data/burden-hira.js` 를 고쳐야 한다.

### 머리줄 고정 · 반응형

열 머리줄은 `position:sticky; top:0; z-index:2` 다. **CLAUDE.md 의 "고정하는 것은 사이드바뿐"
규칙을 이 화면에서만 뒤집은 것이다** — 핸드오프 불변규칙 4가 머리줄 고정을 전제로 쓰여 있다.
앱에 고정 헤더가 생기면 `top` 을 그 높이로 바꾼다.

핸드오프는 데스크톱 조회 화면(컨테이너 max-width 1560px) 기준이다.
1200px 이하에서는 장애인 열을 먼저 접기를 권하고 있는데, 아직 넣지 않았다.

## 특정기호 배지 (표의 구분 칸에 붙는 F018 등)

표 원문에는 없지만 실무에서 같이 보는 값이라 `data/burden-hira.js` 의 섹션에 `codes` 로 따로 둔다.
키는 그 행의 **구분 칸 글자 그대로**이므로, 구분 글자를 고치면 `codes` 의 키도 같이 고쳐야 배지가 붙는다.

```js
codes:{ '자연분만':['F001'], '2세 미만 영유아':['F005','F027'], … }
```

배지에 커서를 올리면 `data/symbol-codes.js` 에서 그 기호의 한글명칭을 찾아 띄운다.
목록에 없는 기호를 적으면 "목록에 없는 기호"로 표시되니 오타를 바로 알 수 있다.

행 이름이 아니라 부담률 칸의 **줄머리**에 붙는 기호(`(임신부)` F015, `(1세미만)` F024)는
`codes` 로는 못 잡아 `js/page-burden.js` 의 `B2_LINE_SYMB` 에서 따로 붙인다.
줄머리 글자를 고치면 이 표도 같이 고쳐야 한다.

목록을 갱신하려면 새 「특정기호_YYYYMMDD.xlsx」를 받아 이렇게 돌린다 (2026-08-24 부터).

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/symbols.ps1 "D:\Documents\Downloads\특정기호_20260824.xlsx"
```

`data/symbol-codes.js` 를 통째로 다시 쓴다. **이 엑셀은 기호 하나에 줄이 여러 개**다 —
명칭이 바뀔 때마다 줄이 늘고 앞 줄에 종료일자가 찍히는 **이력 파일**(1,080줄 → 기호 285개)이다.
화면은 기호 하나에 한 줄이므로 스크립트가 이렇게 묶는다.

- 적용일자 = 그 기호의 **가장 이른** 적용일자 / 종료일자 = **가장 늦은** 종료일자.
  중간의 명칭 변경은 무시한다(2026-08-24 사용자 지정 — "중간에 이름 바뀐건 신경쓰지 말고").
  검산: **F011 = 2015-07-01 ~ 9999-12-31**, **F004 = 2006-01-01 ~ 2017-09-30** (사용자가 준 예).
- **명칭은 이미 `data/symbol-codes.js` 에 있던 기호는 그 글자를 그대로 둔다.** 앞선 판
  (특정기호_20260819.xlsx)에는 「」 가 붙어 있고 이력 파일에는 없는데, 둘 다 심평원 원문이라
  한쪽으로 고칠 근거가 없다. ⑥ 화면의 `SP_F_KEY` 하이라이트도 그 글자에 맞춰져 있다.
  이력 파일에만 있는 기호(끝난 기호 22개)는 **가장 최근 줄**의 명칭을 쓴다.
- 엑셀의 날짜는 시리얼값이라 `[datetime]::FromOADate` 로 **`CCYY-MM-DD`** 로 바꾼다(엑셀 원본에 보이는 꼴, 2026-08-24 요청).

`tools/symbols.awk` 는 기호 하나에 한 줄인 **평면 목록**용이다(예전 판). 이력 파일에는 쓸 수 없다.

### 낱말 단위 배지 (`B2_TERM_SYMB`)

`sec.codes` 는 "행 이름 → 기호" 라, **한 칸에 낱말이 여럿이고 각각 기호가 다른 경우**를 못 잡는다.
차상위 2종 입원표의 구분 칸이 그렇다 — `중증질환자 ※, 고위험임신부, 치매` 한 칸에
고위험임신부(F011)와 치매(V800·V810)가 같이 들어 있다.
그래서 `B2_TERM_SYMB`(표 키 → 낱말 → 기호)를 두고 칸 안의 글자를 찾아 그 자리에 배지를 붙인다.

- **원문 글자는 그대로 둔다.** 배지만 낱말 뒤에 끼워 넣는 화면 처리다(데이터 파일은 안 건드린다).
- 원문에 **글자로 적힌 기호**(`중증질환자 중 특정기호 V191,V192,V268,V273,V275 환자`)는
  같은 자리에서 배지로 바꾼다. `V[0-9]{3}` 이 쉼표로 이어진 덩어리를 잡는다.
- `replace` 를 **한 번만** 훑는다 — 콜백이 끼워 넣은 HTML 은 다시 검사되지 않으므로,
  배지 툴팁 안의 글자에 또 배지가 붙는 일이 없다. 낱말은 긴 것부터 놓아 짧은 것이 먼저 걸리지 않게 한다.
- 표 키(`hi-cs|차상위 2종: E,F — 입원#0`)로 범위를 좁힌다. `치매` 처럼 다른 표에도 나오는 낱말이
  엉뚱한 곳에서 배지를 달지 않게 하려는 것이다.

2026-08-20 에 넣은 것.

| 표 | 낱말 → 기호 |
|---|---|
| 차상위 2종 입원 | 고위험임신부 F011 · 치매 V800·V810 · 6~15세 F020 · 자연분만 F001 · 6세미만 F019 · 제왕절개분만 F013 · 장기 등 기증자의 장기등 적출 F017 · 산정특례 결핵질환자 V000 · 잠복결핵 감염자 F009 |
| 차상위 2종 외래 | 임신부 F015 · 조산아·저체중아 F016 · 치매 V800·V810 · 1세미만 F024 · 건강검진 확진 의료비 지원 F022 · 산정특례 결핵질환자 V000 · 잠복결핵 감염자 F009 |

`구분` 과 `세부` 두 열에 함께 건다 — 외래표는 `임신부, 조산아·저체중아, 치매, 1세미만` 이
세부 칸에도 들어 있다. 입원표에는 `고위험임신부`, 외래표에는 `임신부` 만 있어 낱말이 겹치지 않는다
(겹치면 긴 낱말이 먼저 걸리도록 정렬해 둔다).

글자로 적힌 기호는 자동으로 배지가 된다 — 위 두 표의 `V191, V192`(외래는 `V191,V192,V268,V273,V275`)와
외래 만성질환자 칸의 `V001, V003, … V288` 14개가 그렇다. 낱말을 등록하지 않아도 `V[0-9]{3}` 이면 잡힌다.

### 의료급여 표는 글자로 적힌 기호를 전부 배지로 (`b2Coded`)

2026-08-21 에 넣은 것. 의료급여 표는 기호가 따로 정리된 열에만 있는 게 아니라
`자연분만(F001)` · `6세미만 (F019)` 처럼 **대상 칸 글자 속에** 섞여 있다.
그래서 의료급여 탭(`mg-` 로 시작하는 표)만 칸 글자를 훑어 기호를 배지로 세운다
(`js/page-burden.js` 의 `B2_CODERE` · `b2Coded`). **데이터 파일은 안 건드린다 — 화면 처리다.**

- **`F`·`V` 로 시작하고 숫자가 세 자리**인 것만 기호로 본다.
  상병코드(`F20~29` · `B20~24`)와 `1,000원` 같은 숫자는 걸리지 않는다.
- 괄호가 기호만 감싸고 있으면 **괄호는 지우고** 배지만 남긴다 — `6세미만 (F019)` → `6세미만` + 배지.
- **본인부담구분코드(`M003` · `B010`)는 배지로 만들지 않는다.** 특정기호가 아니고
  `data/symbol-codes.js` 에 없어 말풍선에 띄울 이름이 없다. 글자 그대로 둔다 —
  외래표의 `B010·F015*` 는 `B010·` 은 글자, `F015` 만 배지가 된다(별표는 "동시기재" 각주 표시라 남긴다).
- **건강보험 표에는 걸지 않는다.** 그쪽은 `sec.codes` · `B2_TERM_SYMB` 로 자리를 정해 뒀는데
  여기서 또 훑으면 배지가 두 번 붙는다.
- 검색어가 기호 글자에 걸리면 그 배지를 **뒤집어**(파란 바탕·흰 글씨, `.symb.hit`) 보여 준다.
  배지 안에 `<mark>` 를 넣으면 배지 바탕과 같은 연한 파랑이 겹쳐 표시가 나지 않기 때문이다.

붙는 곳은 입원 29개 · 외래 37개다(2026-08-21 기준).

## 메모장 기본 메모

`data/memo-seed.js` 는 사내 엑셀 「총진료비,본인부담금 계산식.xlsx」의 **마지막 시트 Sheet2**
(A열 제목 · B열 내용 · C열 비고, 118행)를 옮긴 것이다. 메모장을 처음 열 때
`js/page-memo.js` 의 `seedMemos()` 가 localStorage 에 한 번만 넣는다.

- 넣고 나면 플래그(`samguide_memo_seeded`)를 세워 두 번 넣지 않는다.
- 같은 제목의 메모가 이미 있으면 그 항목은 건너뛴다 — 직접 적어 둔 메모를 덮지 않게.
- 넣은 뒤에는 여느 메모와 같다. 고치거나 지운 것을 이 파일이 되살리지 않는다.
- 제목의 줄바꿈은 공백으로 폈다. 제목 입력칸이 `<input>` 이라 줄바꿈을 담지 못한다.
- C열(비고)이 있는 행은 본문 끝에 `[비고] …` 로 붙였다.

엑셀이 바뀌어 다시 만들려면 Excel COM 으로 Sheet2 를 읽어 `{t, b}` 배열을 JSON 으로 찍고
파일 머리말을 붙이면 된다. 다시 넣으려면 브라우저에서 두 키를 지운다.

```js
localStorage.removeItem('samguide_memo_seeded'); localStorage.removeItem('samguide_memos');
```

같은 엑셀의 다른 시트(상해외인 · 시범사업 · 특정기호 · 희귀,중증 등)는 아직 쓰지 않았다.

## 상해외인 · 시범사업

둘 다 같은 사내 엑셀 「총진료비,본인부담금 계산식.xlsx」의 시트를 옮긴 것이다.
Excel COM 으로 시트를 읽어 `{…}` 배열을 JSON 으로 찍고 파일 머리말을 붙이면 된다.

**상해외인 시트** — 원문 표는 병합 셀이 여러 줄로 풀려 있다. B열(구분 코드)이 채워진 줄에서
다음 코드 전까지가 한 건이라, 그 사이 줄의 각 칸을 공백으로 이어 붙여 `data/injury-codes.js` 를 만든다
(예: 입(내)원일수의 `"중복된 "` + `"일수 제외"` → `"중복된 일수 제외"`). 글자는 고치지 않는다.
F열은 원문 표에 없는 **사내 메모**라 `note` 로 담고 화면에서 회색 상자로 구분해 그린다.
맨 아래 두 줄(MT037 · MT065)은 `INJURY_NOTES` 로 빼서 표 밖 각주로 그린다.

**시범사업 시트** — S001~S050 이 모두 적혀 있지만 내용이 채워진 것은 14건뿐이다.
채워진 것만 `PILOT_CODES` 에 담고 빈 기호는 `PILOT_BLANK` 에 남긴다 —
"본인부담금이 없는 것"이 아니라 "아직 안 적은 것"이라 화면에서도 체크박스를 켜야 보인다.

같은 엑셀의 특정기호 · 희귀,중증 시트는 이미 `data/symbol-codes.js` ·
`data/special-codes.js` 가 심평원 원본에서 만들어져 있어 쓰지 않는다.
